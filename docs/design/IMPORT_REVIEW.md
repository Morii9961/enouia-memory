# Enouia Memory · 历史导入与审核流水线

版本：设计包 v1.0 / 2026-09-28。来源定义见 [DATA_MODEL](DATA_MODEL.md)，提交见 [总架构](MEMORY_ARCHITECTURE.md)。

## 1. 导入范围与次序

首先支持用户主动选择的 ChatGPT 导出包 / conversations.json、Markdown 迁移档案，以及由本项目自己定义的 Runtime native session 格式。Claude / Codex 会话 importer 是后续独立适配器；不得拿现有 Activity usage collector 冒充会话导入器，也不读取登录凭据。

设计时没有取得真实导出样本，因此不假定某个未公布 JSON 结构永久稳定。MV-2 用已知合成结构与用户选择的脱敏样本做能力探测；未识别格式可以先保全原件，再显示 unsupported，而不是猜测并丢字段。

平台内部 Memory 摘要只能作为来源种类为 summary 的材料；没有官方可用能力与实际账户验证前，不承诺读取、完整复制或双向同步平台内部记忆。MCP 工具调用也不是整个会话全文的自动捕获。

## 2. 一次导入的完整流程

1. **检查与预览**：验证选择的文件/目录，显示总大小、可用空间、格式、预估对象数；拒绝路径穿越、压缩炸弹、符号链接/reparse 逃逸、绝对路径与重复危险文件名。
2. **保全原件**：流式复制用户交给系统的实际字节，计算 SHA-256，二次验证，登记 raw manifest。取消时已有对象留在隔离 staging，可按事务恢复；不显示 archived_complete 直到原件完整提交。
3. **解析与归一化**：按 adapter version 输出 SourceRecord、会话关系和附件引用。把解析成功、跳过、隔离、错误数量分别统计；所有未知字段仍由 Raw 保留。
4. **分支与覆盖分析**：记录父子关系、编辑/重生成分支、当前分支若上游有提供，以及各分支缺口。不得把所有分支串成同一条发生顺序。
5. **幂等对账**：按对象哈希、来源命名空间和上游 ID 对账；同消息多次导出不产生多条正式记忆。内容变化保留来源修订。
6. **提交可浏览来源**：归一化来源分批以完整事务提交，固定 resume cursor 与 parser version。原件保全成功后解析可以失败而不丢原始资料。
7. **生成导入报告与备份**：报告覆盖范围、附件可用情况、警告、哈希清单、最后恢复点。确认至少一份独立加密备份可读后，才进入真实批量抽取。
8. **提取候选**：默认人工或确定性规则建立候选；启用模型抽取须先通过 MV-7 的外发边界与预算。候选尚未被接纳不能进入普通回答上下文。

导入状态为 planned → archiving → archived → parsing → completed / partial / failed；extraction 是独立任务状态。Raw 完整但附件缺失时只能称“收到的导出字节完整归档”，不能称平台历史完整迁移。

## 3. ImportManifest 与覆盖报告

必须保存 import_id、input_kind、input_hashes、received_at、adapter/version、source_schema_observed、account_scope、original size、归档对象清单、解析批次/水位、warnings、归一化计数、重复计数、错误计数及附件状态分布。

覆盖表按账号/会话/分支给出 earliest/latest source time、source message count、platform asserted count（仅上游有提供时）、missing parents、unparseable records、已知的未覆盖日期。导入日期和最新消息日期必须分开展示。

没有消息 ID 的 Markdown：以原始文件哈希 + byte span 定位，不用标题制造全局唯一会话。重新导入修改过的文件产生新的来源版本，可能与旧文件重复；先提示关联，不自动断定同一事实。

## 4. 候选抽取的质量约束

抽取输入是有范围的来源片段及其前后语境，不把完整导出一次塞进模型。按对话分支和话题切块，保留适当上下文重叠；跨块重复候选由来源引用与命题 fingerprint 提示合并，不通过字符串近似直接提交。

候选应当能回答：是谁的什么信息、适用何时何处、原话在哪里、为何值得保留、是否有不确定/否定/条件语气。模型回答“你一直喜欢某事”若没有用户证据，保持 model_claim；模型 confidence=0.99 也不能提高证据等级。

区分以下信号：

| 信号 | 处理 |
|---|---|
| 用户明确作出的长期决定 | 候选优先展示，带原句与确认范围 |
| 用户试探、愿望、可能计划 | tentative，保留条件，不改为已实现 |
| 模型提议未经用户确认 | model_claim 候选或忽略，不能成为用户偏好 |
| 笑话、引用、角色扮演、否定句 | 默认不提为事实；提议时标语境 |
| 健康、关系、财务、位置 | private/highly_sensitive；不从蛛丝马迹补充推断 |
| 重复出现的说法 | 增加证据关联，不把重复次数当真实性 |
| 密码、令牌、恢复码 | 隔离与告警，不进入记忆正文、embedding 或日志 |

抽取任务保存 input source hashes、extractor/prompt version、目的、Provider、支出上限、批次游标、输出候选 IDs。可暂停/重试；同一批次响应丢失重跑最多产生重复候选提示，不重复接受记忆。预算耗尽停止剩余抽取，不影响已归档历史。

## 5. Review 的真实交互

审核页同时显示候选文本、来源片段、来源角色和时间、当前相关记忆、差异、敏感度、外发策略及冲突。接受按钮对应精确 revision；编辑后重新生成确认摘要。不能默认勾选整个历史库的候选。

- Accept：来源完整且约束成立，生成正式记录及 ReviewRecord。
- Edit：用户修改正文/分类/时间；保留模型原提议和用户最终批准文本。
- Reject：保存拒绝与可选理由；后续抽取不重复烦扰，来源发生实质变化时可提出关联新候选。
- Merge：明确合并目标及保留的命题范围，保存所有支持证据，敏感等级默认取较严格者。
- Supersede：预览新旧事实及生效时间，事务级切换，不销毁过去。

审核 backlog 超过本地阈值时暂停自动抽取并提示消化候选；建议初值 500 条待审/每批展示 20 条，作为可调产品参数，不构成事实丢弃策略。暂未抽取的 Raw 完整保留。

## 6. 日常会话与恢复

原生会话由 SessionService 先保存用户输入、再调用 Provider、最后保存实际结果。取消、断网、超时和模型切换均作为事件；不存在完整回复时不生成“任务完成”的 checkpoint。

外部聊天通过 memory_propose / session_checkpoint 只能送入提供给工具的文本和证据；若没有原始消息可核验，登记 agent_submission / partial。以后导入完整导出可以追加证据关系，但不会倒改当时所知道的内容。

跨窗口接续输出三部分：已审核长期事实、最近分支 checkpoint、尚未解决或需要重查的事项。用户选择继续的是具体会话或项目，不根据相近标题自动合并两个活跃窗口。两个窗口同时修改同一项目时 expected_revision 拒绝过期写入，并提供重新对比入口。

## 7. 本流程必须留下的证据

每次导入都有可读报告和对象清单；每次抽取都有范围与预算；每次审核都有用户确认和提交点；每次恢复都有覆盖范围。最终验收同时检查字节保真、解析覆盖、分支关系、来源可达和拒绝项不入上下文，不能只比较“摘要看起来合理”。
