## 先回答 Morii 的问题

**已经做到 MCP 了，但尚未完成真实客户端日用闭环；本地基础核心已经很扎实，记忆认知逻辑还没有做完。** 当前六个工具已有受限 stdio 协议和同一 Host 内的合成领域接线。外部 Agent 的原生认证与接入、真实 MCP 客户端、Runtime 对该 Host/版本的采用、真实双 Provider 及个人验收，必须分别核实，不能以本地测试替代。

目前记忆的主要路径是：收到的原件被保护，解析为有角色、时间和定位的来源；规则或模型提出候选；主人检查来源、范围、冲突与敏感度后，候选才成为正式记忆。检索在权限、删除、来源及有效期等约束内选出相关记录，再按确定性规则装进 Context。纠正保留替代链，归档退出默认召回，删除另走影响预览和确认。MCP 只是让其他客户端在这些规则内回忆和提议，既不会自动取得整段聊天，也不会让模型直接批准正式记忆。

Morii 感到初始化“提取了内容，但维度不够”，这个判断有实际依据：数据结构已经能表达五类记忆及一些时效信息，普通抽取通路却主要生成 fact / preference，主体、项目、情境、事件区间、关系变化、未竟事项及情绪的来源归属还没有形成完整质量闭环。**安全地存下来，与忠实地理解经历，是两项不同工作。** 本轮没有打开私人 Vault，因此不把历史候选数量或私人内容覆盖率当成已核实现状。

## 建议的方向

保留 Enouia 的来源、修订、权限、单主和恢复底座，将人工准入改为可追溯的系统自动准入，并迁入 Ombre 式形成、巩固、情境召回与衰减机制。记忆格、时间轴、星图与模拟器共享同一组来源和记忆身份，成为观察与纠正自动系统的窗口；人工操作是可选控制，不是使用前提。

OmbreBrain-folio 值得迁入的不止交互，还包括自动写入、打标、组织、浮现与衰减。整套替换也可选，但现有数据格式、Runtime adapter 和来源/历史语义不会自动兼容。推荐先隔离比较原版行为，再选择认知引擎整合方案；具体差异与迁移代价见新说明，不能因旧版人工审核约束而拒绝自动化。

下一轮重点调整为“可靠捕获 → 自动提炼与准入 → 下次自动使用”的闭环，再扩周期巩固和自然淡出。含糊与冲突由系统暂存、重评或弃答，不积成必须由 Morii 清理的队列。原件与版本可恢复，重要性、可信度和活跃度分开。
