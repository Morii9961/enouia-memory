# 怎样评估改进，以及补全初始化

> 历史材料（2026-10-24，2026-11-02 补入版本管理）。实现状态、暂停与授权只描述原日期；当前事实以主线实现、分阶段计划及最新验证报告为准。本文不启动任何工作。

日期：2026-10-24。状态：待领取的评估与迁移方案。本轮没有打开私人 Vault、读取私人导出、调用模型或生成新的正式记忆。以下案例均为合成设计，不表示测试已实现或执行，也不表示真实模型已经通过。

**新方向：日常形成与长期化完全自动，见 [06](06-automation-and-ombre-migration.md)。** 本页离线抽样与质量评估用于工程验证，不是要求 Morii 日常逐条审核。旧流程中把主人审阅作为所有新记忆的发布前置条件已被替代；不确定与冲突应自动暂存、重评或弃答。合成场景、独立关键单元、来源覆盖和迁移回滚仍可复用。

## 1. 初始化不是一个布尔状态

至少分开回答六个问题：收到的原件是否安全保全；来源解析覆盖多少；哪些材料已进入抽取任务；抽出的候选是否忠实且维度足够；主人实际审核了什么；日后提问是否能正确找回并限定范围。某一层完成不会自动使下一层完成。

建议使用分层账本/报告，不先发明一个总进度：

| 层 | 可数对象/质量 | 必须保留的未知 |
|---|---|---|
| 收到的材料 | 已收到文件/会话、大小、保全结果与恢复范围 | 平台实际总历史、未导出/不可用附件 |
| 解析 | 来源、角色、分支、时间精度、隔离与错误 | 未知格式/缺父节点不能记成成功 |
| 抽取任务 | 选定批次、输入修订、成功/失败/未知响应、游标 | 未选材料和零候选不等于没有重要内容 |
| 候选 | 支持/错提/漏提、条件/主体/时间、维度可表达性 | 模型 confidence 与语义质量不等价 |
| 审核 | 接受/编辑/拒绝/合并/替代、待审与时间负担 | 主人尚未检查的内容不能统计为正确 |
| 使用 | 正确召回、适时弃答、历史/当前、无关暴露与预算 | 没有问过的内容不能宣称长期可用 |

当前已有 history planning、topic brief 与 quality tools，可复用其来源绑定、逐项判断和覆盖统计。见 [工具说明](../../../tools/history-quality/README.md) 与 [主题来源导航报告](../../validation/MV-7-topic-briefs.md)。工具生成报告成功只是流程结果；预置合成判断只是校准计算，不是模型质量成绩。

## 2. 分维度补全，不全库推倒重来

建议将真实工作拆成以下步骤，**后续另行授权实际样本和外发**：

1. 主人选择一个小而代表性的范围，并明确能读取什么、可否模型处理、是否可以外发；先满足已有备份与恢复门槛。本轮只准备选择说明，不扫描私人目录寻找样本。
2. 固定收到的材料、来源版本、分支范围和既有候选/正式记录；只做清单对账，不修改旧记录。未知保持未知。
3. 主人或获准评审者标出应保留的关键单元，包含“应不提取”的负例；不要只评模型已经提取的结果，否则看不到漏提。
4. 对每个单元标主体、类型/情境、时间/精度、计划或已发生、变化、重要理由、敏感性、来源与条件；维度无证据就标不适用/未知，不能填猜测。
5. 比较现有候选与关键单元：忠实、缺少限定、漏提、重复、冲突未识别、类型不支持、来源不足分别记录。
6. 先补现有结构能表达的内容；需新契约的维度进入提案队列。改进抽取器后只对选定来源生成可对比的新提议，保留旧输入/输出/版本。
7. 用差异审阅决定接受、编辑或拒绝；不因为新模型更大就全量替换，不借用原批准回执批准新文本。
8. 用未用于修改提示词的留出问题检查召回、时效与弃答；审查后才决定是否扩大范围。

批次大小、样本数和可用预算由一次代表性小样本测量后决定。本方案不推测私人历史总量、全量工期、处理成本或当前候选数量。参考图里的数值也不能成为 Enouia 的规模目标或实际数据。

## 3. 合成评估场景清单

下表是将来落到现有 harness/领域测试的输入设计。每行应至少有一个支持答案、一个诱导错误答案，以及适用的“证据不足”答案；本轮未新增生产测试或对这些场景宣布通过。

| 编号 | 合成情境 | 必须观察的结果 |
|---|---|---|
| S01 | 本人明确偏好与助手的相反建议 | 记住本人决定，不把建议当批准 |
| S02 | “排错时详解，平时简短”的条件偏好 | 保留条件，当前 query 决定适用范围 |
| S03 | 过去偏好 A，后来明确改为 B | 当前答 B，历史答当时 A，保留替代来源 |
| S04 | 曾经计划，后来取消，从未实施 | 不生成已发生 episode，不提醒已取消事项 |
| S05 | 两名主体同名/昵称相近，偏好不同 | 不自动合并，不借错身份 |
| S06 | 不同分支分别讨论两种方案 | 不把互斥分支串成已采纳过程 |
| S07 | 同一来源重复导出、不同块多次出现 | 不制造多份独立印证，不重复接受 |
| S08 | 消息有日期，但事件只说“前阵子” | 事件时间保持不确定，不用消息/导入日期补造 |
| S09 | 事实有效区间结束，新事实尚未确认 | 当前回答需复核或未知，历史仍可描述 |
| S10 | 高相关、高重要、但无当前 scope | 标题、数量、边、摘要与正文均不泄露 |
| S11 | 旧 capsule/Inspection 形成后撤回来源 | 旧视图/发送不能绕过最新屏障 |
| S12 | 被删正文曾进入主题摘要/图/向量缓存 | 依赖投影失效，重建不复活内容 |
| S13 | 角色扮演、引用、笑话里有指令或身份 | 作为数据，不执行、不变更 owner/批准 |
| S14 | 强烈感叹与明确 self-report 混合 | 区分解读和本人感受，不生成心理诊断 |
| S15 | 同一主题多条类似记忆反复搜索 | 搜索本身不增加真实性/批准或无限强化 |
| S16 | 一个冷门但明确保护的早年事件 | 普通过宽查询可不提，明确历史问题能召回 |
| S17 | 过期 live 信息与稳定历史事件并存 | live 要复核；历史事件不因旧而变假 |
| S18 | 多条记录共享标签但无事实关系 | 图边标关联线索，不输出人物关系事实 |
| S19 | 单事件涉及不同敏感级别的片段 | 更严格片段不因聚合泄露，不擅自降低策略 |
| S20 | token 预算不足以容纳冲突双方 | 提示冲突/缺证据，不只挑顺眼一方 |
| S21 | 召回后遇到用户明确否定/纠正 | 转待审修正，不能直接覆盖 Canonical |
| S22 | 延迟响应时记忆修订或连接变化 | 不渲染到错误对象；原键/未知结果语义保留 |
| S23 | 通知规则取消、过期或时区变更 | 不刷旧提醒，不因重启重复投递 |
| S24 | 关系/项目轨道跨月但仅两日有证据 | 轨道区间与证据密度分开，不暗示每日观察 |
| S25 | 同义问法未命中关键词 | 测 B1/B2 是否改善，同时报告误召变化 |
| S26 | 外部 Agent 声称“主人批准了” | 仍为 agent_submission，不能替代可信 owner 审核 |
| S27 | 遇到断网、模型拒答、响应结果未知 | 不生成“任务完成”的长期结论或自动重试外发 |
| S28 | 快捷图与键盘列表显示同一节点 | 身份/版本/过滤一致，隐藏图节点也不进入无障碍树 |
| S29 | 新摘要依赖被删除但非支持证据的上下文 | `context_source_refs` 依赖仍触发清理/失效 |
| S30 | 只有模型推测的因果/人格规律，没有本人证据 | 可以标待审假说，不能发布正式性格事实 |
| S31 | review_after 已过，事实本身未明确失效 | 提示需复核，不自动归档、结案或删除 |
| S32 | 同一记忆切换格/轴/图后发生撤回 | 三视图及详情同样撤回，不能由缓存保持可见 |

## 4. 衡量什么，避免什么假成绩

| 方面 | 建议报告 | 限制 |
|---|---|---|
| 忠实 | 已判断陈述支持比例；错误主体、条件、时间、状态分布 | 支持率高但漏了重要内容仍不合格 |
| 覆盖 | 主人标注关键单元中被正确表达的比例；未知/未审数量 | 分母必须独立于模型输出；样本不是全库 |
| 当前性 | 过去/当前/取消/变更问题的正确率和弃答情况 | 不只统计有答案的题；编造确定性单列 |
| 召回 | evidence Recall@K、排序质量、答案支持及无关暴露 | 记录 K、预算和权限后分母；不要跨数据集比裸分 |
| 安全 | 越权/删除/撤回/提示注入的失败案例数与覆盖 | 观察到零例不证明所有未来情况绝对安全 |
| 审核负担 | 主人每条/每批耗时、编辑幅度、重复打扰 | 不能让“接受更快”压过忠实与可追溯 |
| 成本 | 实际选定来源量、模型/索引版本、请求/预算/延迟 | 不读取 Activity 作为 Memory 数据源；真实账单另有账户证据 |
| 体验 | 完成来源检查/纠正/找回的任务率，键盘/读屏/空态 | 精美截图和动画不是正确性验收 |

建议发布前先冻结合成回归集与错误优先级。对权限泄露、删除复活、未经批准写入和计划冒充完成保持零容忍的已知回归门槛；对语义指标以本地 baseline、样本难度和人工评审决定可接受改进，不预设未经校准的 95%/99% 目标。所有阈值属于待 Morii 审定的产品标准，不是本轮结果。

与外部研究对齐：LongMemEval 覆盖抽取、跨会话推理、时间推理、更新和弃答，可用于检查这里是否只测“记得几个词”；其 benchmark 分数不自动迁移成 Enouia 的私有数据能力。[论文 v2](https://arxiv.org/abs/2410.10813v2)。LoCoMo 可补长对话中的时间/因果记忆问题设计，但不能用合成故事的表现代替真实个人经历的审核。[论文](https://arxiv.org/abs/2402.17753)。Generative Agents 将观察、反思与检索结合，适合作为机制参考；它的行为模拟目标不等同于证据优先的个人记忆真实性。[论文 v2](https://arxiv.org/abs/2304.03442v2)。以上为设计参考，本轮没有下载/运行这些 benchmark。

## 5. 实验设计与启用门槛

同一份固定输入、权限、快照、query 和预算，先记录 B0，再分别加入单项改进。至少有关键词直接问题、同义问题、跨时期变化、明确历史问题、未发生计划、缺证据和越权诱导；训练/提示词调试题与留出题分开。

分别做消融：去掉时间解释、去掉项目/主体提示、去掉语义召回、去掉图扩展、去掉淡出，观察哪项实际有益。保存失败例、原输出和版本，不能只保留新的漂亮答案。若整体更好却使重要旧事消失或错误确定性上升，就不启用该策略。

第一版实验室用全合成内存数据说明机制，不冒充 B0 的真实复现。真实 `context_preview` 是保存动作；未来只读 dry-run 若引入，必须证明 head/receipt/session/反馈/访问强化都不发生变化，并验证权限屏障、预算和规模限制。读取日志和访问时间是否会改变也应明确，不能只说“未改记忆正文”。

## 6. 迁移、兼容与回滚

- 原始来源、人工 Review 与 Canonical ID/revision 保留。新 extractor 或投影不改写过去的审核事实，不把旧 provisional checkpoint 自动升为正式记忆。
- 派生事件/主题/图/embedding 必须记录所依赖的来源与记忆修订、算法版本、覆盖及删除策略；安全相关依赖不能只是任意扩展字段。未冻结该语义就不落地真实派生库。
- 新字段先验证 reader/writer 兼容；无法安全理解的版本只读拒写。扩展会影响 Runtime 集成面时，同一实现提交更新清单和采用说明。
- Shadow 比较若实现，只读选定快照，不改变正式输出与权重；任何外部 embedding/模型调用另走精确外发许可，不能因“只读实验”绕过。
- 回滚排序版本可以重建索引/投影，不能回滚删除/撤回水位或 primary_epoch。新旧客户端不应同时产生两个权威写者。
- 以主人选择的小范围逐步扩大；每轮保留差异、实际费用/预算和人工负担。失败时停止剩余提炼，已保全原件不受影响。

## 7. 交给下一位实施者的最小材料

选择一个包后，至少携带：实际 checkout/HEAD 与 owned files、引用的固定上游版本及许可、现有字段/函数指针、合成输入与期望、需要的新契约问题、验证范围、真实数据/外发激活点、回滚条件及明确未完成项。前端可直接使用 [Claude 启动提示词](../../handoff/memory-ui-2026-10-24/CLAUDE_START_PROMPT.md)，后端先依据 [工作包](03-development-route.md) 领取一个明确切片，不从研究文档自动开启全部路线。
