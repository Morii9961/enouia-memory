# Enouia Memory · 产品愿景与范围

版本：设计包 v1.0 / 2026-09-28。规范依赖：[总架构](MEMORY_ARCHITECTURE.md)、[分阶段计划](IMPLEMENTATION_PLAN.md)。

## 1. 要保护的连续性

Enouia 的连续性由 Morii 自己掌握的历史、身份约定、关系语境、项目决策和未完成事项支撑。模型负责理解与生成，客户端负责交互，Vault 负责保存可检查的依据。

这是一项数据与运行时工程目标：换模型、换窗口、重装客户端后，仍能找回“说过什么、确认过什么、做到哪里”。它不承诺不同模型回答逐字一致，也不把保存人格描述等同于证明某种主观意识延续。

优先级依次为：可恢复、可追溯、所有权、隐私、可阅读与可迁移、上下文准确性、使用便利。前几项没有成立前，不以自动化程度或 UI 丰富程度衡量成功。

## 2. 六个核心使用场景

| 场景 | 用户得到的结果 | 必须说明的限制 |
|---|---|---|
| 平台窗口不可用 | 从本地来源与最近 checkpoint 接续，并查看最后覆盖时间 | 未导出的平台对话无法凭空恢复 |
| 查询过去的项目选择 | 找到决定、确认来源、时间及后续变更 | 设计已定不等于代码已完成或上线 |
| 切换 GPT / Claude / 本地 Provider | 使用同一组已批准记忆与会话边界 | 模型能力、上下文窗口、工具权限可以不同 |
| 新聊天产生长期信息 | 看到候选、原文、冲突和建议操作，确认后保存 | 模型推断不能自行升级为已确认事实 |
| 电脑离线 | 本地仍可浏览、搜索、编译上下文；VPS 可排队事件 | 没有本地模型时不能承诺离线生成回答 |
| 磁盘或 VPS 丢失 | 从独立加密备份恢复，或重建网关 | 故障后可恢复范围取决于最后成功备份/同步点 |

## 3. 分三个完成层次交付

**救援底座（MV-1～MV-2）**：原始文件可验证归档，导入可重跑，用户能知道哪些历史与附件实际到手；基础备份可恢复。此时不宣称记忆理解已完成。

**本地 Memory MVP（MV-1～MV-5）**：人工审核、五类记忆、时间和来源、搜索、Context Compiler、会话 checkpoint、离线 Mock、损坏恢复全部成立。最小命令行/测试驱动界面可操作，Windows 完整 UI 和真实模型不是 MVP 的先决条件。

**可日用与远程延伸（MV-6～MV-10）**：Windows 浏览与审核（v1.2：由 Runtime 客户端承载，见 ADR-MEM-45）、实际上下文检查、真实 Provider、MCP、VPS 队列、手机/PWA 的受限接续依次开放。每个外部集成独立验收；不因本地 MVP 完成就声称支持全部聊天平台。

## 4. 明确的范围

首版只面向 Morii 单一所有者，但保留设备、客户端、Agent、Provider 的不同主体身份与权限。一个所有者不代表所有进程都可以读取所有内容。

五种长期语义类型为 Fact、Preference、Episode、ProjectState、SessionCheckpoint。运行时自动 checkpoint 是 Session 工件，只有经过审核的 checkpoint 才进入第五种 Canonical 类型。此区分避免模型总结自动变成长期事实。

关系语境与身份风格可以长期保存，但只能由 Morii 审核修改。系统不得从一时的玩笑、情绪或模型自述推断新的身份、关系规则或健康结论。检索是否相关与是否允许传给外部模型分开判断。

## 5. 本设计不扩大到的工作

- 不重新实现 Activity 收集、统计、Moriium 上传或网站展示。
- 不构建多用户平台、知识图谱优先系统、多 Companion 治理或自主人格审批系统。
- 不实现电脑监控、后台剪贴板读取、自动抓取聊天网页、语音/Avatar 或自动执行生活事务。
- 不把记忆中的“以后请做某事”变成工具执行权限；行动仍需当前任务授权。
- 不把当前规划直接发布到公共仓库；迁入公开 Runtime 文档前须检查私人路径和实例。

## 6. 成功如何被判断

成功首先由可重现的行为证明：离线打开历史、引用到原文、接受和拒绝候选、更新旧事实、重建索引、切换 Provider、恢复备份。相关指标与失败用例在 [ACCEPTANCE](ACCEPTANCE.md) 中逐项定义。

真正的最终交付应让 Morii 清楚看到：系统记住了什么、为什么相信它、它描述哪一天、这一轮把什么发给谁，以及最后可恢复到哪里。
