# Enouia Memory · 验收矩阵与证据标准

版本：设计包 v1.0 / 2026-09-28。除末尾“本轮文档检查记录”外，本文全部是未来实现验收要求，当前均未执行。

## 1. 验收规则

每条验收记录包含 ID、环境/版本、fixture 或脱敏输入标识、操作、期望、实际结果、证据文件、通过/失败/pending。没有真实资源时保留 pending，不用 Mock 替代真实兼容性结论。禁止把生产凭据或私人会话当公共 fixture 提交。

修复以受影响范围复验；固定不变的证据可以复用。数据可靠性、安全边界和恢复必须有失败路径，不只做 happy path。性能目标注明机器、库规模、冷/热状态和样本数。

## 2. 契约与领域边界

| ID | 测试 | 通过条件 |
|---|---|---|

| D02 | 主版本与迁移 | 未知 major 不可写；失败迁移保留旧 CURRENT；成功迁移可从升级前快照恢复 |

## 3. Vault 与事务

| ID | 测试 | 通过条件 |
|---|---|---|
| V01 | 双进程/UI+CLI 同时写 | 只允许一个 writer；第二个返回 busy 或在规定等待内安全排队 |
| V02 | staging/对象/manifest/CURRENT 各边界终止 | 读者只见完整旧/新提交；未发布对象不会变成记忆 |
| V03 | CURRENT 发布后响应丢失 | 重试同键同正文返回同一 receipt；不同正文报冲突 |
| V04 | 接受候选同时 supersede 旧记录 | 候选状态、review、新旧记忆共同提交，不出现半套状态 |
| V05 | 磁盘满/权限拒绝/共享冲突 | 旧状态可读，错误明确，重试不复制正式记忆 |
| V06 | CURRENT/单对象损坏 | 检测并报告范围；不猜最新 manifest，不静默丢数据 |
| V07 | 路径穿越/reparse/网络与同步盘根 | 管理写入不逃出受控根；未验证数据根拒绝启用 |
| V08 | 读时并发提交/撤回 | 内容 pin 一致快照；发送前最新删除/权限生效 |
| V09 | 可靠性等级 | 分别记录进程终止、OS 重启/故障、断电实验；无断电实验不能宣称 power-loss verified |

## 5. 记忆治理

| ID | 测试 | 通过条件 |
|---|---|---|
| M01 | 未批准、拒绝、撤回候选 | 都不参与普通 Canonical 检索和模型请求 |
| M02 | Agent 伪造用户批准/导入“记住”文字 | 无可信 review 不能提交，不能变 owner |
| M03 | 人工编辑与批量旧 revision | 精确批准正文一致；冲突时不部分成功却报告全部完成 |
| M04 | 证据来源与角色 | 模型自述不能变用户确认；每条正式记忆至少一条可定位证据 |
| M05 | supersedes 与循环 | 新旧记录保留；环、跨范围误替代与不存在目标被拒绝 |
| M06 | 业务时间/已知时间 | 事后导入不回写系统过去的认知；历史选择可重现；未来生效的替代不会提前隐藏当前事实 |
| M07 | 相互矛盾的事实 | 不以 confidence/时间自动取胜；冲突可见且有审核入口 |
| M08 | Identity/关系改变 | 普通工具不可写；用户 diff 确认、版本、恢复路径完整 |

## 8. Provider、安全与备份

| ID | 测试 | 通过条件 |
|---|---|---|
| P01 | 删除全链路 | Canonical/Raw 包/候选/会话/capsule/索引/备份/副本有影响清单和状态，无假全局删除 |
| P02 | 两种实际 Provider | 受控真实调用均以同一批准证据回答并保存 Dispatch；无资源时 pending |
| P03 | 目的地、敏感、密钥 | private 逐次确认，highly_sensitive 不自动外发；凭据不入 UI/日志/备份 |
| P04 | 错误/重试/自动 fallback | 不向未授权模型发送，不把失败 token 流当完整答复 |
| P05 | 抽取成本与候选隔离 | 限额停止、任务可恢复、重复提议可识别；不自动接受 |
| P06 | 锁定、撤回、审计不可用 | 新外发与受保护读被阻止；在途请求结果如实标 unknown |
| B01 | 独立加密备份与新环境恢复 | 不依赖原索引/工作目录/本机 DPAPI；对象与审核来源一致 |
| B02 | 旧备份与删除 | 恢复先对账删除/设备撤回，不自动把忘记内容重新上传 |
| B03 | 密钥轮换/遗失与备份损坏 | 验证可恢复或明确不可恢复，坏快照不覆盖健康库 |
| B04 | 本地保护与日志扫描 | 真实数据启用前验证 ACL/卷保护，索引/临时目录受保护，日志无哨兵正文 |

| ID | 测试 | 通过条件 |

| X01 | 单 Host / 多客户端 | 不存在 UI/MCP 双主，版本不匹配不可并写 |
| X02 | 工具最小权限 | propose 不能 commit；read 不能 source；超范围返回无泄漏错误 |
| X03 | HTTP auth | issuer/audience/expiry/scope/撤回验证，令牌不透传 |
| X04 | 工具幂等与限额 | 重试同结果，旧版本冲突，超量读取不可绕过分片限制 |
| X05 | 实际聊天客户端连接 | 按产品/版本记录 transport、认证、工具成功与缺口，不泛称通用兼容 |
| G01 | 接收持久化/重启 | 返回 durable_received 的事件能在服务重启后恢复 |
| G02 | ACK 前后断线 | 本地先提交；ACK 丢失重投不会重复正式应用 |
| G03 | 游标缺口/乱序/lease | 不越过未处理事件；租约过期安全重投；dead letter 可见 |
| G04 | 磁盘满/配额/重放/伪签名 | 不先确认再丢弃；非法请求被拒，正文不入日志 |
| G05 | 本地离线 | 事件排队；读请求快速 offline；无假远程全记忆能力 |
| G06 | 删除 VPS | 本地 Canonical 完整；排队未同步事件从队列备份/上游恢复或明确报告损失 |
| G07 | 服务隔离 | 不触碰 Moriium 目录/密钥/公开契约；重新部署不改变本地记忆所有权 |
| N01 | 密文设备副本 | VPS 无解密秘密；被授权设备可解密并验证完整性 |
| N02 | 有限服务副本 | 仅批准子集、到期失效、明确服务端可见，不声称服务器不可解密 |
| N03 | 旧 manifest/回放 | 验证 epoch、水位、签名与 TTL；拒绝已知回退 |
| N04 | 离线冲突/撤回/删除 | 无 last-write-wins 覆盖；离线设备未确认时如实 pending |
| N05 | Primary 迁移/旧主回归 | 新 epoch 只允许一主；旧主只能只读/候选，不恢复写权 |
| N06 | 备份与同步区别 | 删除/损坏不会瞬间吞掉全部独立恢复点；恢复按最新删除账本过滤 |

## 10. 质量与性能基准

| ID | 目标 | 测量方式 |
|---|---|---|
| Q01 | 检索质量 | 固定至少 60 条 query 的 golden 集，覆盖中文、项目、历史、否定、歧义、敏感；报告 Recall@10、误召回和无证据问题处理 |
| Q02 | 本地响应 | 10,000 Canonical + 100,000 source messages、16 GiB RAM/SSD 参考环境，热索引 100 次查询，编译 p95 目标 ≤300 ms；不含网络/模型 |
| Q03 | 增量收益 | embedding/新排序相对 FTS 基线报告准确率、延迟、存储、成本与隐私回归；不能只展示两个成功例子 |

安全 golden：未授权外发、未审候选进入 Canonical、删除后检索复活的容忍度为 0。功能 golden：核心 20 条 MUST 查询（含 MoriMeta 的无证据变体）预期 IDs/状态 100% 一致；其余探索集首版 Recall@10 目标 ≥0.9，达不到时记录失败并修正，不操纵标注。

导入/重建额外测 1 GiB、100,000 消息合成库，记录峰值内存、耗时、取消延迟、恢复耗时与磁盘放大；初始目标工作集额外内存不超过 1 GiB、长操作取消反馈 ≤2 秒。磁盘 flush 和不可中断 OS 操作的最坏延迟单独记录。50 GiB 恢复目标来自 PRIVACY_RECOVERY，不能用 1 GiB 小样本证明。

## 11. 发布与完成定义

本地 MVP 要求 D/V/I/M/R/C/S、P01、B01～B04 中对应阶段用例通过，I07 真实样本缺失须明确标注兼容未验。用于 Morii 的真实私人 Vault 前，I07 和恢复门槛必须完成。Windows、真实 Provider、MCP、VPS、副本各自增加对应套件，不能把一项完成等同于全系统上线。

每次发布同时说明 schema 兼容、升级前备份、回退条件、未覆盖故障、实际支持平台。停用或卸载程序默认保留 Vault；删除数据必须走用户确认的独立流程。
