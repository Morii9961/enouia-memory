# Enouia Memory · 隐私、备份与恢复

版本：设计包 v1.0 / 2026-09-28。本文定义安全与运营要求；所有验证结果须在对应阶段产生，本设计不宣称现有设备已加密或备份已运行。

## 1. 保护对象与威胁边界

要保护正文、附件、关系/健康/财务细节、项目内容、可推断个人信息的检索索引、访问记录与密钥。威胁包括设备遗失、同机其他用户、不可信文件/来源、恶意 Agent、误批候选、Provider 外发、VPS 入侵、密钥丢失、恢复旧备份导致删除资料复活。

用户账户已被完全控制、已授权模型保存了所见内容、攻击者已复制明文等情况，单靠 Vault 无法撤回全部影响。防护重点是最小化暴露、明确授权、保留证据、限制后续访问及可恢复操作；不以“用了加密”声称所有风险消失。

## 2. 分级与默认外发

| sensitivity | 本地所有者 | 已授权普通 Agent | 外部 Provider / embedding | VPS 可计算副本 |
|---|---|---|---|---|
| public | 可读 | 仍需该工具/项目 scope | 当前请求配置允许即可 | 明确选择后可加入 |
| normal | 可读 | 显式项目范围 | 每个 Provider 的明确持续授权 + 相关性过滤 | 默认关闭，显式逐范围启用 |
| private | 可读 | 默认不授予，单独范围许可 | 初版逐次展示确切内容并确认 | 默认不允许；MV-10b 单独决策 |
| highly_sensitive | 本地受限读取 | 默认拒绝 | 初版拒绝自动外发；用户主动受控导出另行确认 | 禁止 |

原始导入和未知分类默认 private，候选不得自行降级。已发现的密码、API key、恢复码属于 secrets，放隔离/秘密处理流程，不是可供检索的“highly_sensitive 普通记忆”。模型不能把 sensitive 改成 normal；人工降级也必须有 diff 和审计。

访问策略同时检查主体、项目、类型、来源范围、操作、目的、目的地、有效期和撤回状态。授予 memory:read 不等于 source:read，不等于 provider:send，也不等于备份/同步整个库。新主体与未知目的地默认拒绝。

派生数据默认继承来源最严格等级。若把含私人内容的来源改写成不含私密信息的低敏陈述，必须记录人工 declassification review；不能仅因摘要变短就自动降级。Caption、OCR、向量、capsule 与 checkpoint 同样受约束。

## 3. 本地静态保护

首版选择：可读 JSON/Markdown + 用户受限 NTFS ACL + 已验证的全盘/卷级加密 + 独立加密备份。真实私人数据启用前须检查数据盘和临时目录保护状态；本轮没有运行该检查。纯合成开发不要求先改变 Morii 的设备配置。

这不是应用级文件加密：用户登录、磁盘解锁后，获授权的系统账户可看到明文。初版“锁定 Vault”关闭 Core 读取/模型外发/Host 会话、清除进程缓存和令牌，不能把一个已解锁普通目录变成密码保险箱。UI 必须如实说明。

若未来需要在同账户下防其他程序直接读 Vault，另立应用级加密容器阶段，覆盖 Raw、附件、索引、临时目录、审计与崩溃转储。必须解决锁定、检索性能、恢复密钥及可读导出，不允许只加密 canonical.json 却留下明文 FTS。

Provider 凭据与本地解锁包装使用 OS 秘密存储 / 用户级 DPAPI，避免 machine-wide 可解密范围。DPAPI 通常绑定用户和设备，所以不能作为迁机恢复的唯一办法；加密备份的恢复秘密必须独立保管并进行新设备恢复测试。[Microsoft CryptProtectData](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)

## 4. 备份设计与密钥所有权

**基线备份工具选择 restic 适配器**，对固定提交点的可迁移导出做加密备份，避免项目自创备份密码学协议。实现时固定安装版本、校验来源、验证 Windows 支持与恢复行为；本轮未安装、未执行。restic 官方资料描述其加密仓库及按 snapshot 恢复能力，这只是工具选择依据，不能代替本项目的恢复测试。[restic References](https://restic.readthedocs.io/en/stable/100_references.html)、[Restoring from backup](https://restic.readthedocs.io/en/stable/050_restore.html)

备份账户与恢复秘密由 Morii 控制。运行端可用受保护包装读取备份密码；离线恢复副本存入独立密码管理器/安全介质。不要把唯一恢复密钥只放在同一磁盘、同一 VPS 或仅 DPAPI 的本机包装中。VPS 保存密文备份时不拿解密密钥。

默认目标为三份资料、至少两种故障域、一份离线/异地加密副本。只有本机磁盘内复制不算独立灾备。云对象存储或 VPS 是可选目标，未配置远端时允许独立外接盘先完成救援备份。

### 备份一致性步骤

1. pin 已提交 CURRENT、policy/deletion epoch，并建立受保护的 backup lease，阻止期间 GC/purge 删除所需对象。
2. 生成完整 manifest：版本、vault_id、提交、对象哈希、来源与附件覆盖、会话事件截止水位、候选/review/receipt、权限、删除清单、设备与同步恢复元数据；审计以已封口 segment 为止。
3. 创建固定可读导出或受控快照视图，随后对它执行加密备份；不让备份程序边读不断变化的 CURRENT 边猜测一致性。临时明文只在同受保护卷，结束后清理。
4. 排除可重建索引与可重新获取的缓存；凭据不进备份，恢复说明列出哪些凭据需重新配置。审核、会话、去重与删除信息不能排除。
5. 验证加密仓库可访问、manifest/对象抽检通过，写 BackupReceipt，再释放 lease。涉及彻底删除时取消相关备份任务，不能让旧 lease 无限保留已删除正文。

索引通常不备份。若某阶段确实需要 SQLite 一致副本，使用数据库官方备份机制或受控停写快照；不得复制活跃 DB 文件而忽略 WAL。[SQLite Backup API](https://www.sqlite.org/backup.html)

### 默认频率与目标

| 项目 | 设计目标，尚未测量 |
|---|---|
| 本地已确认写入 | 进程崩溃不丢已返回 committed 的事务；断电级别另测 |
| 独立自动备份 | 主机在线时每日增量；重大导入/迁移前后额外快照 |
| 主机/磁盘完全损毁 RPO | 目标不超过 24 小时；以最近成功独立备份为准 |
| 恢复 RTO | 50 GiB 参考库、可用本地备份下目标 4 小时内可读；索引可随后完成 |
| 恢复演练 | 首次真实导入前演练合成库，首次真实导入后抽检，每月完整隔离恢复一次 |
| 保留 | 建议 14 日、8 周、12 月；删除要求可覆盖该保留计划 |

电脑长期关机、备份介质断开、密钥遗失会使这些目标失效；面板显示实际 backup age，不能仍然显示“每日已保护”。容量不足先停止自动抽取、暂停新导入并告知，不能自动删 Raw 救空间。

## 5. 恢复 runbook

1. 停止写入与外发；保留故障目录的只读副本及诊断，不原地尝试破坏性修复。
2. 选择已知有效快照和恢复目的地，验证恢复密钥、版本、manifest 与对象哈希。
3. 恢复到独立目录；验证来源引用、审核状态、supersession 无环、所有关键对象、会话末尾完整性、删除账本。
4. 对账是否有比该快照更晚的 tombstone、设备撤回和 primary_epoch。无法确认最新撤回状态时只进入所有者恢复查看模式，禁止 Provider、MCP 与远程同步，明确旧数据可能已被删除过。
5. 在隔离目录重建索引，执行核心黄金查询与来源打开；显式标出超过备份水位的可能缺口。
6. 用户确认后切换数据根/恢复指针并写恢复收据；重新配置凭据、轮换受影响设备凭据，再开启网络。
7. Activity 恢复完全独立；Memory 恢复不读写其 sequence、pending 或生产调度。

恢复测试必须在原索引不存在、原工作目录不可用、Provider 断网情况下通过。若所有本地与独立备份及恢复秘密都丢失，系统无法保证恢复，界面不得给相反承诺。

## 6. 删除、忘记与不可变历史

不可变指日常不覆盖；它不剥夺 Morii 删除自己数据的权利。分三种明确操作：

| 操作 | 实际效果 |
|---|---|
| 更正 / supersede | 旧事实保留为历史；默认当前检索不使用 |
| 忘记 / logical delete | 立即写 tombstone，撤销检索与外发，保留受限正文以备撤销 |
| 彻底删除 / purge | 删除已选正文及所有可管理派生副本；保留不含正文的删除回执 |

logical delete 先提交 tombstone 与 deletion_epoch，再取消包含目标的待发送请求、使 capsule/缓存/索引失效。已发给外部 Provider 的内容无法由本地召回；记录目的地供用户按其可用删除流程处理，不声称一键抹除所有外部存储。

purge 先做影响预览：Raw 对象、其他引用它的记忆、来源、附件、候选、会话、checkpoint、capsule、embedding、索引、staging、导出、备份、设备/Gateway 副本。所有共享引用均要处理，不能删除一条路径后别处仍可检索。

若一条消息嵌在保存整个 conversations.json/ZIP 的 Raw 对象中，不能声称只删分离消息就清除了原件。用户选择删除整个包含对象，或保留经过清洗的新对象并明确“原件已按用户请求销毁，新件非无损原件”；重新建立来源定位与 provenance，保留范围化回执。新 Raw 的默认 immutable 从新对象生效。

已清除正文的旧 commit 允许保留最小引用/哈希和 tombstone，但历史查看返回 intentionally_purged，不将其当完整可恢复历史。GC 必须理解删除覆盖和引用关系，不把有意清除误判成普通损坏并自动从备份“修复”。

备份中仍有副本时，删除状态为 live_deleted / backup_purge_pending，并显示最晚清除日期；需立即清除时重建干净备份、验证后移除旧快照及相关保留对象。同步/离线设备未确认时继续列出 pending，不显示 globally_erased。SSD、文件系统快照及已复制数据不能保证物理逐位抹除；使用经过验证的加密生命周期减少残留风险，不承诺普通文件删除就是安全擦除。

## 7. 审计与日志

所有领域接口读写按请求记录 who/when/operation/which IDs/purpose/destination/result；拒绝也记录脱敏结果。直接用编辑器读取明文目录不在应用审计能力内，不能声称覆盖所有 OS 文件访问。

普通诊断仅有组件、错误类别、耗时、计数，不含 query、正文、文件名、原始异常、认证 header。访问审计同样属于私人资料，限制 ACL、轮转/加密备份，建议访问日志保留 90 天；必要审核/提交证据按记忆生命周期保存。

Canonical 写入的审计证据属于同一提交事务；读取/Provider 外发需先保证审计记录可写。审计不可用时外部读与外发 fail closed；本地仅允许受限健康诊断与恢复流程。记录请求获准和网络结果时，发送后崩溃无法确认对方是否收到，标 unknown，不能重试后伪称从未外发。

不默认遥测、崩溃上传或远程原文日志。调试导出须人工预览脱敏内容。哈希链可发现部分篡改，但管理员能改数据和本机链；若需要更强篡改证据，使用独立保存的签名检查点，不能称普通 append-only 日志为不可篡改账本。

## 8. 故障行为矩阵

| 故障 | 系统行为 | 恢复路径 |
|---|---|---|
| SQLite 丢失/损坏 | Index=Recovering，记忆文件仍可浏览；不返回旧缓存冒充当前 | 重建同一提交点索引 |
| commit 前进程终止 | 旧 CURRENT 继续有效，新 staging 不可见 | 校验后清理孤儿，不自动接受候选 |
| commit 后响应丢失 | 写已发生，客户端显示待确认 | 幂等 receipt 返回原结果 |
| 单对象损坏 | 隔离受影响记录，阻止依赖它的外发 | 已验证备份恢复并报告影响范围 |
| CURRENT 无法验证 | Vault=Recovering / 只读，不猜最新文件 | 选择有证据的安全提交或备份 |
| 磁盘满/共享冲突 | 保留旧状态、拒绝新提交，不清空队列 | 释放空间/处理占用，再幂等重试 |
| 模型超时 | 保存已提交用户输入和失败事件，记忆不受影响 | 用户重试或选择获准 Provider |
| VPS 不可用 | 本地完全可用，远端请求失败/本地 outbox 保留 | 恢复网关并对账游标 |
| VPS 丢失 | 已同步本地记忆不丢；尚未同步事件可能丢 | 队列独立备份/上游重投；报告缺口 |
| 恢复旧快照 | 默认网络关闭 | 对账新删除与 primary epoch 后再连网 |
| 主机遗失 | 撤回设备与 Provider 凭据 | 新机隔离恢复、重新授权、主设备接管 |

## 9. 上线门槛

合成开发可以推进，不必读取任何私人聊天。真实历史启用前必须完成本地保护检查、独立加密备份与恢复演练；真实 Provider 先有外发预览和目标授权；MCP 先有认证和范围；VPS 先有队列持久化及独立恢复；远程可计算副本最后单独选择资料与信任范围。

这些是未来实施门槛，不是本轮要求 Morii 立即改系统设置或批准上传。当前规划可以完整交付，具体资源只在相应阶段进入实际使用前落实。
