One policy-revocation run did not receive its denial reply; a focused rerun did.

[Microsoft](https://learn.microsoft.com/en-us/windows/desktop/api/namedpipeapi/nf-namedpipeapi-disconnectnamedpipe).

with no data, or OutcomeUnknown with the exact original packet/key retained and
a closed client afterward. It also proves the native reader is revoked. No
deadline/ACL/permission is relaxed, no retry is added, and teardown does not wait
indefinitely for a peer to drain a denial reply.
