Seven synthetic tests cover coverage/unknown dates/role preservation, pagination and stable repeated reads without commits or tasks; stale parameters/head/opening; wrong Vault/import revision, duplicate imports, strict path refusal and reference limits; current SourceRead policy; adapter/received-size refusals; revision through a later import; and source-dependent purge through ordinary proposal/review/forget operations. The 64 MiB refusal uses a genuine oversized synthetic blank Markdown archive; immutable archive size is not weakened to manufacture a fixture. Contract/schema fixtures add one valid request/response and bounded-argument negatives.

## Verification and its limits

The required workspace command was run with default test concurrency and again with `-- --test-threads=4`. Both runs reached all seven passing history tests. The first failed the existing `lifecycle_waits_for_an_in_flight_page_call` and `closing_during_purge_waits_for_the_complete_response_and_expires_replay` status deadlines; both passed individually. The four-thread run passed those two but returned `fault.writer_busy` in `concurrent_session_new_replays_the_published_session_and_branch`. These complete-command failures are retained, not reported as green runs, and their precise cause under concurrent suite load is not established.

Without changing production lifecycle behavior, waits or assertions, `cargo test --workspace --lib --locked -- --test-threads=1` then passed all 114 library tests, including all 73 Workspace tests and their internal concurrent scenarios. The four-thread run had already passed every preceding package/integration group (316 tests, including 41 library tests repeated by the serial run). Together this covers 389 distinct passing tests; `cargo test --workspace --doc --locked -- --test-threads=1` also passed (zero doctests). It does not prove the default-parallel suite is stable.

Strict all-target workspace Clippy and Rust format checks passed. The independent Python 3.12/python-jsonschema 4.26.0 check passed 36 schemas, 55 valid records, 119 record cases, 4,913 set records, 51 IPC messages, 90 Workspace messages, 46 store documents, 8 Provider-invocation cases and 19 extraction-job cases. Runtime surface generation/check records and logs aggregate `575548bf9f94c887deeb0463d08f53e18a59a5aff6f8af233a72f7161974f197`. Documentation links/fences, public-content inspection and whitespace checks passed.

The necessary opt-in Windows crash-injection correction is a separate supporting commit, documented in [its report](Vault-crash-injection-2026-10-19.md); normal storage and fault-free behavior are unchanged.

Limitations: this is local embedded-Core development evidence, not native Windows UI, actual historical completeness, semantic quality, production scale or owner acceptance. A 64 MiB archive/decompression or 100,000-message limit can require smaller owner-selected exports. Binding is deliberately strict: every parsed message must have a current source citing that exact import/Raw object. Overlapping or delta imports whose unchanged sources were reconciled into earlier imports, or whose earlier sources were revised, may be refused; no inferred cross-import lineage is added here. Planning does not authorize extraction; later H2 use must validate its own current bindings and governance rules.
