# MV-7 native text Provider implementation

Date: 2026-10-08. Baseline: `8197890`. Scope: Memory repository only.

The owner explicitly started MV-7 and then instructed: implement functionality first, defer real smoke. This report records native Rust functionality and synthetic acceptance. It does not mark the MV-7 real-account exit gate passed. No real API credential was read/written, no real account was accessed and no HTTP call was made during validation.

## Implemented

- OpenAI Responses and Anthropic Messages text requests, canonical exact-body inspection, model/destination binding and strict JSON/SSE decoding. OpenAI disables storage/automatic truncation; native HTTPS disables redirects, implicit proxies and automatic retries, with bounded input/response/timeout/cancellation.
- Saved external Context compilation retains approved evidence and source references, applies destination-specific standing policies, and keeps local Mock serialization/behavior. Native owner policy grant/revocation plans are hash-confirmed. Governance `AcceptWithEgress` binds explicit egress metadata through the existing reviewed plan; ordinary approval does not enable external use.
- Private content needs an exact, expiring, single-use per-request approval. Highly sensitive content is refused. Current policy/deletion/lock/restore gates and durable audit precede HTTP admission. Missing credentials, capabilities, approval, quota or audit fail without an attempt.
- Admission atomically persists immutable Dispatch, message bodies, full wire body and a Session invocation reservation. Same input/dispatch cannot be resent, even with an unknown/crashed outcome or a new dispatch ID. Known usage, terminal errors, local token/price reservations and incomplete length results are retained.
- Reported input totals include Anthropic's separate cache-creation/read counts while avoiding double-counting OpenAI's cache breakdown or Anthropic's nested creation breakdown. JSON/SSE share bounded count validation; absent usage remains unknown, malformed usage fails before completed publication.
- Later token admission debits the higher of each earlier immutable reservation and its known reported token sum. Underestimated reservations cannot conceal known overruns; lower/unknown usage never refunds the reservation floor. The same rule respects saved extraction token ceilings.
- Stream chunks are saved before delivery. Responses inherit the strictest carried evidence sensitivity. Publishing private text checks original policy/deletion epochs against the writer's pinned head; final delivery checks authorization again. EOF is never completion.
- Stream decoding rejects out-of-order message phases and conflicting stop reasons, supports Anthropic's multiple top-level/cumulative usage updates and retains optional values when omitted/null. Parser or persistence errors latch permanently, so trailing failures cannot later become a completed result.
- Output whitespace remains byte-for-byte intact, including separate space/newline chunks and whitespace-only terminals. Empty deltas do not create stored chunks; valid zero-text terminals preserve completion/length and usage without leaving an unknown ledger. Blank user input remains refused.
- Exact archived inspection and saved results survive reopen. Native terminal event/content, exact outcome, usage and errors publish in one Vault commit; terminal replay binds all that metadata. Local receipt repair remains for legacy separately saved terminals without HTTP. Existing dependent deletion now covers full request archives and length-failure response bodies; the shared-evidence purge leaves a clean Vault.
- Disabling the native adapter blocks protected reads, preparation, approval, local recovery and late terminal publication. An admitted result refused after disable remains unknown until a local terminal receipt exists; the host still owns cancellation/join on lock/close.
- An exact-hash native owner interruption plan can close an unfinished unknown local turn after worker joining. The local cancelled outcome retains partial text, immutable admission and reservation floors, does not claim remote cancellation, and allows only a new explicit user turn to continue. Known/legacy saved results cannot be overwritten.
- Standing grant/revocation confirmation plans privately bind the original local Vault ID and root, refusing transplantation to an identical copied history. Existing inspection bytes, policy/approval records and same-root replay remain unchanged; the root path is not serialized or displayed.
- Extraction pause/resume pins before job/source validation, so concurrent cursor/control changes cause a revision conflict without a stale control commit. Existing immutable history also protects completed jobs.
- OpenAI terminal event kinds must match nested completed/incomplete response status. Contradictory metadata permanently fails before completion/length publication, retaining partial chunks and one-attempt behavior.
- Native HTTPS preflight refuses entered Tokio contexts before credential reads/admission and before direct transport runtime creation. Unsupported host execution returns a structured, nonretryable setup error without consuming the exact call's approval, reservation or attempt; custom transports retain an allowed default.
- Local native credential-shape validation runs before audit/admission, preserving private approval and budgets when an existing UTF-8/size/control-byte rule refuses the secret. Direct native exchange shares the same rule before runtime creation; custom transports retain opaque/binary secret support by default.
- Failed/cancelled streams retain the last validated normalized usage with their atomic terminal outcome. Later token admission includes these known counters, while missing counters remain unknown and reservation floors are retained; malformed later events cannot overwrite the known report or authorize completion/resend.
- Native Windows credential read/write targets are restricted to the two named Provider entries. Those functions are compiled, not exercised against the owner's credential store.
- Optional source-bound extraction persists immutable selection/prompt/binding/budgets and progress. Whole-response JSON/quotation validation precedes proposals; candidates remain pending, with source-derived evidence class/sensitivity. Pause, local cursor receipt recovery, unchanged reviewed-claim suppression and bounded pending backlog are enforced. Source-dependent deletion erases undispatched input too. Immutable job token/monetary caps survive reopening and constrain the caller’s Session quota; required prices cannot be omitted. Input safety margin is reserved for tokens and cost.
- Local extraction preview returns literal citations and source metadata, preserving UTF-8 offsets in resolved source text and the difference between the model's original proposal and the current owner-edited/reviewed candidate. Paused jobs remain inspectable; the preview never writes or sends and refuses a changed pinned view.
- New `extract-text-2` inputs preserve source occurrence/capture time, precision, branch uncertainty and selection offsets. The local preview includes complete selected text so qualifiers outside the literal quote stay visible. Version-1 saved jobs remain valid and unchanged.
- Preference extraction requires actual user evidence. Imported/agent consent claims never promote a model claim to user preference evidence; invalid later preferences refuse the full response before publication. Pending facts retain actual model evidence and uncertain status.
- Extraction application binds the original job input before state/replay handling, matching preparation and preview. A later input in the same Session cannot advance an old job or receive its completed replay through the wrong adapter; the correctly bound adapter still resumes normally.

## Synthetic acceptance

`crates/enouia-memory-provider/tests/providers.rs` uses isolated Vaults, synthetic evidence, fake secrets and fake byte transports. Its original 13 cases cover both API envelopes, exact archives/replay, private approval and changed wire refusal, missing keys/capabilities/lock/quotas, admitted crash/new-dispatch refusal, fragmented UTF-8 SSE, both streaming terminal/truncated cases, network failure, reopen/local receipt recovery, explicit price ceilings, shared reviewed evidence and purge, standing-policy revocation, length-preserving incomplete outcomes and cancellation. The shared-evidence case also proves that private evidence yields a private result in an otherwise normal Session.

Seven additional extraction cases cover both APIs, source-only preparation, no canonical writes, enable/pause/resume, invalid later claims leaving zero candidates, unchanged rejection suppression, changed-key/UTF-8/backlog refusal, reopen after injected publication failure, deletion before dispatch and durable token/price/pause admission limits. Nineteen extraction-job fixtures distinguish schema shape from typed cross-field constraints, accept both supported prompt versions and reject unknown versions. Storage validation also binds source content hashes and candidate IDs; added property cases prove scoped/whole-set equivalence for extraction jobs.

Contract/schema acceptance adds eight positive/negative invocation cases, checked independently by serde/domain validation, the Rust subset validator and pinned python-jsonschema. Existing fixtures remain synthetic; no Runtime checkout, fixtures or target directory is used.

A further adapter-disable case checks archived/saved reads, local recovery, preparation and late-result refusal without a new Vault commit, then verifies unchanged unknown admission and protected reads after re-enabling.

The preview case checks a narrowed Unicode source selection, exact citation offsets, source role/time/class preservation, unchanged Vault head, paused inspection and latest owner edits separately from original proposals, plus disabled/wrong-owner refusal. Existing invalid-quotation and reviewed-suppression cases also check preview rejection and current rejected/suppressed states.

A context case checks that version-2 wire input and preview preserve an explicitly unknown occurrence time and branch alongside the archival timestamp. Complete selected text retains negation and conditions outside the model quote. No canonical memory is accepted; quotation containment remains separate from semantic correctness.

A both-API agent-consent case first reproduced acceptance of an unsupported model-evidence preference, then verifies whole-response refusal with no candidates/cursor/head changes. A fact-only response from that same agent source stays pending with `model_claim` evidence and uncertain status, even though the source claims user consent. It never enters the canonical view.

Two stream cases cover premature/open-block/conflicting stop updates, reopening blocks after top-level updates, trailing errors after a valid terminal for both APIs and failure latching. The positive case covers multiple top-level updates with cumulative counters, late input usage, and omitted/null values preserving prior known metadata. The initial negative case reproduced the old order-acceptance gap. The implementation follows the official Anthropic event flow/types linked in the native guide.

Two usage cases reproduce cache input undercounting, verify both providers' totals without double-counting breakdowns, and cover late/null cache updates in streaming. Negative checks cover absent versus malformed usage, non-object data, negative/string/fraction/boolean/out-of-range counts and sum overflow. Both-API native calls with malformed reported input publish a failed turn and no saved completed response, with one synthetic HTTP attempt; malformed SSE counts permanently fail decoding. Actual invoice rates/costs remain unverified.

A both-API two-turn quota case first reproduced admission that ignored a known reported overrun. It now verifies the next call is refused before HTTP/ledger publication when actual reported usage is higher than the old reservation, and also when a low usage report would otherwise refund that reservation. The prior admitted result and original reservation are retained.

Two atomic-terminal cases cover both APIs, completed/length results and injected I/O failure immediately before/after `CURRENT` publication. Reopened state contains either the unknown admission with no terminal, or the exact result/usage together in one additional commit. Published results require no ledger repair, identical replay does not advance the head, changed usage conflicts, and neither side permits resend. Invalid dispatch binding, state/event pairing and completed error metadata refuse without publication. This is fault-injected local persistence evidence, not a real process kill or power-loss drill; the existing legacy receipt-repair case still passes.

Two output cases first reproduce the rejection of a standalone whitespace chunk, then cover both APIs, completed/length states, mixed and wholly whitespace output, Anthropic initial block text, and empty deltas. Chunk bytes/order match the nonempty input fragments exactly. Zero visible text in JSON/SSE still saves exact finish/usage in one terminal commit without partial chunks or repair/resend permission. Blank owner input and direct empty chunks refuse with no head change. Empty content objects use the existing zero-size contract; schemas and stored shapes are unchanged.

A metadata case first reproduces an actual serde-json panic when an Anthropic start usage array receives a later counter update. It covers malformed start/update usage shapes and counts, wrong delta/stop types, later valid values masking an invalid earlier value, and overflow introduced only by merging a partial update. All failures are immediate, do not panic, and latch across subsequent push/finish. Missing/null initial usage remains unknown while later reported output is retained. The native fake transport records one failed invocation and refuses resend; no completed response is published.

A closed-turn case first reproduces native admission of a prepared request after a generic local terminal event, despite no prior Provider ledger. Both APIs now refuse completed, cancelled and failed turns before admission/HTTP, leaving no invocation/reservation and no new Vault commit. This includes a local Mock reply ending the input before native sending. The terminal-event view is pinned by the existing optimistic admission commit; a concurrent close cannot be silently reopened.

Two local interruption cases cover both APIs after reopening an unknown admission with a saved partial chunk. Planning has no head change/content exposure; wrong hash/surface/owner/root, disable and expiry refuse. Fresh confirmation adds one atomic terminal commit, replays its ID without writes, retains nullable usage/reservation and partial bytes, and never resends the old input. A new explicit user input can send, but only if its token ceiling includes the retained old reservation. A pre-existing legacy terminal receipt is never overwritten; local recovery retains its completed reply. These are synthetic native API checks, not host worker-join or remote-cancellation evidence.

A policy-plan case first reproduces a grant being committed to another physical synthetic Vault with the same owner, Vault ID and exact CURRENT history. Both grant and revocation now refuse such a copied-root confirmation without changing either head; the original confirmation remains usable and an identical same-root replay adds no commit. Both Vaults verify clean. The binding is private in-memory metadata and changes no policy/approval wire or storage shape.

A deterministic in-test thread race holds pause/resume during source permission validation while another Vault handle advances one or both candidate cursors. Before the fix, a stale control silently succeeded after partial progress; completed-history validation already refused reopening with `InvalidRequest`. Both delayed pause and delayed resume now return `RevisionConflict` against partial or complete progress and add no commit. Saved progress/candidate IDs remain intact, fresh partial-job controls still work, completed application replays without writes, the fake HTTP count stays one, and the Vault verifies clean. The race still uses real in-test concurrency with a single harness worker.

An OpenAI terminal-status case first reproduces acceptance of an incomplete event carrying a completed response. Both contradiction directions now fail immediately; a later correctly typed terminal and `finish` remain refused. The native client persists exactly one local failed terminal, retains the saved partial chunk, exposes no completed/length saved response, and refuses resend without another fake HTTP call or Vault commit. Both underlying nonstreaming bodies remain valid for their own statuses, and existing matching stream cases remain covered. The consistency rule and official generated event definitions are linked in the native guide.

A native context case first reproduces a nested-runtime panic during `Client::send` in an async Tokio context. After preflight, both APIs return nonretryable `InvalidRequest` before the counting synthetic secret store is read, with no invocation or head change. Direct native transport use also refuses without a byte callback; the outer runtime still yields normally. An entered synchronous Tokio context is refused conservatively too. A separate fake transport then uses that still-unconsumed exact call once inside the synthetic runtime, proving default/custom preflight compatibility. Credentials are empty synthetic bytes: no OS credential access or HTTP occurs, even if the context guard regresses. This does not establish live HTTPS or actual host worker acceptance.

A malformed-credential case first reproduces an invocation being consumed before empty synthetic credentials are locally refused. Both APIs now refuse empty, invalid UTF-8, CR/LF, NUL, DEL and oversized credentials before admission, leaving no invocation/head change and preserving an exact private approval. Direct native exchange refuses the same shapes without delivering bytes. Every negative shape already fails before network sending even in the pre-fix native implementation; no HTTP or OS credential access occurs. A separate fake transport supporting opaque binary secrets then admits the same approved call once, proving preserved approval and default/custom compatibility. The saved result is completed and the Vault verifies clean. No server-side key validity or account access is claimed.

A failed-stream case first reproduces validated usage being discarded when a later stream error closes the turn. Both APIs now retain their known input/output counters across transport failure, cancellation and malformed trailing events. Anthropic's pre-stop prefix includes normalized cache input; OpenAI's valid terminal usage remains known even if a later event or transport error prevents local completion. Saved partial text stays present, no completed response or resend is allowed, identical failed-terminal metadata replays without a commit and changed counters conflict. A new explicit input whose ceiling would cover only the old reservation is refused before fake HTTP or ledger publication because the retained report is higher. Each synthetic Vault verifies clean. No count is estimated from text and partial reports do not establish final billing.

A both-API input-binding case first reproduces a later input's adapter advancing a saved old extraction job in the same Session. Preparation and preview already refuse that mismatch. Application now refuses before any state handling, covering ready, paused, partially applied and completed jobs without candidate/cursor/head changes. The original adapter still previews, pauses/resumes, applies both candidates and replays completion without writes; the fake HTTP count stays one and the Vault verifies clean. During fixture setup, retaining an old index while rebuilding another caused `SharingViolation`; releasing that test-owned handle fixed the fixture before the actual behavior was reproduced. No product index/locking logic changed.

## Host adoption and acceptance still pending

[ADR-MEM-47](../adr/047-explicit-provider-dispatch.md) and the [native guide](../integration/PROVIDERS.md) document the API flow and failure semantics. [Runtime's compatibility row](../integration/RUNTIME.md) records adoption duties. `SessionRecord.provider_invocations` and `extraction_jobs` are omitted when empty; existing Mock sessions retain their previous serialization. Populated ledgers/jobs are rejected by older strict Session readers, so the Runtime pin must be updated before enabling Provider-generated sessions.

Workspace IPC/reference UI still call Mock; Runtime product Provider controls, native credential setup, worker cancellation/disable/join and rendered/native acceptance are not implemented in this checkout. Core does not depend on the HTTP crate. Real account/model capabilities, pricing, exact tokenizer integration, actual HTTP transport/SSE behavior and live cancellation remain unverified. Subscription ownership is not treated as proof of API access.

This slice estimates token input from full UTF-8 wire bytes plus a margin; it is not an exact tokenizer guarantee. Reservations/price caps apply per Session, with explicit caller-supplied rates, not global account spend. Unknown admissions never auto-refund or resend. Legacy recovery of a terminal length result saved separately from its ledger may conservatively retain `failed` and unknown usage; new native terminals publish exact metadata atomically. Optional model extraction (MV-7.4) is implemented as an explicit native flow and remains inactive in the host. Its candidates enter the existing owner review queue. Only fact/preference claims are supported; literal quotations are verified for containment, not semantic truth. Raw objects over 64 MiB are refused before allocation. Precise snippet offsets remain in the job/prompt/response and the local native preview; candidate evidence retains whole-source locators. MV-8 has not started.
