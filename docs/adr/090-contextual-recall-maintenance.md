# ADR-MEM-90 — Contextual recall and derived attention maintenance (Core-6)

Date: 2026-10-24. Status: Adopted for explicit synthetic native use. Morii
authorized continued Core work. Real models, migration, Runtime adoption and
notifications retain their separate boundaries.

Keep current authentication, policy/deletion/source/lineage gates ahead of
candidate counts, ranking, aliases and trace. Add a deterministic versioned
lexical/alias/condition/time selector over eligible latest revisions. Historical
selection still uses current authorization, not old grants. Keep knowledge,
adoption, attention and explicit plan state separate. No vectors are required.

Use a bounded native AttentionProfile as retrieval tuning, never a permission
grant. Fading and archive affect default accessibility, not truth, completion or
physical deletion. Protect reported episodes/relationship experiences by profile;
explicit related historical queries can recover archived eligible material.
Search does not touch, reinforce or modify any record. Fix algorithm, clock and
ties for replay; return authorized reasons and actual rendered-byte truncation.

One opt-in bounded native Memory maintenance thread periodically writes a
disposable content-free attention projection under indexes. It is derived from
the current root and original-source capture times, not a second authority.
Business reads recompute through fresh gates and never trust cached eligibility.
Lock/deletion/cancellation stops use or future ticks; no notification/delivery
port or action executor exists. No Activity/Usage, frontend timer, real Provider
or default worker activation is added. See [contract](../contracts/CORE6_RECALL.md)
and [evidence](../validation/CORE6-recall.md).
