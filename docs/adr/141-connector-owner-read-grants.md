# ADR-MEM-141 — 连接器独立的主人只读授权

日期：2026-11-11。状态：**Morii 已明确同意独立只读授权边界；PR #103 已合并，真实采用待定**。
这是既有 ChatGPT 连接器路线的核查片，不启动新 MV 阶段。
ADR140 属于并行初始化会话；本提案不改变它的输入、形成策略或生产入口。

## 当前事实

基线 main `45de3c0`，PR98～101 已合并。核查和测试使用独立分支及虚构 Owner 根。
证据见[验证报告](../validation/Connector-read-policy-semantics.md)。

| 层次 | 当前职责与期限 | 原生入口 |
| --- | --- | --- |
| 形成策略 `AutomationPolicy` | 来源、主体、项目、敏感度及创建/修订权限；有 active、valid_from、valid_until；当前也约束后续读取 | Vault 的 Owner-only `set_policy` API；不能把 JSON 当授权。旧 reinit 驱动的七天策略属于形成，不是长期读取决定 |
| 记忆的 `PolicyRef` | 形成时的策略 ID、修订和完整内容哈希；没有独立有效期，不随策略更新而迁移 | 内嵌在保存的 admission/decision 中，不应重写 |
| Agent 范围与短许可 | Agent 身份、主体、项目、策略、来源、敏感度、source_read；最长五分钟，不能超出当前形成策略期限 | 原生 initialized reader；远程服务从启动时读入的配置每约四分钟换代，结束旧 MCP 会话 |
| OAuth 令牌 | 证明已批准的客户端持有 `memory.read`；不授予具体 Vault 行权限 | remote `approve` 加已有 DCR/PKCE；access 一小时，refresh 每次轮换并重新计三十天；不能把 refresh 当作固定三十天的 Vault 授权 |

`State::policy` 只匹配当前策略的精确引用；`State::authorized` 和 Agent 的
`policies_current` / `allows` 都执行相应检查。测试确认：

- 同 ID、修订加一且只延长有效期：旧许可拒绝，新许可可读获准来源，但旧记忆及其历史为空；原生 System 视图也不返回该记忆。重开结果一致。
- 另建 ID，关闭创建/修订权限并覆盖同一组来源：可以读来源，不能接管旧记忆；旧形成策略到期后亦如此。
- 停用再启用旧策略，仍产生新修订；既有记忆不会自动恢复读取。

这些是当前精确绑定的实际语义，不据此宣布实现缺陷，也不放宽现有门槛。

## 确有缺口的主人管理能力

已有 `serve` / `approve`，但没有面向此 Owner 布局的完整长期授权管理入口：
无法原生列出持久只读授权、查看其生效范围和历史绑定、独立续期或撤回。
配置文件不是独立持久授权，修改后须重启才能应用。OAuth 的 family revoke
目前仅用于重放处理，没有主人查看/主动撤回客户端的命令。
授权页的批准码也不展示或管理 Vault 读取范围。

只增加 CLI 包装 `set_policy` 不能填补这个缺口：延期会改变哈希，而且可能延长
形成/采集权限。只重发 OAuth 或延长 bearer 则不会改变 Vault 的精确绑定。

## 已确认的最小边界

增加**显式选择的、持久的 Owner 只读授权**，与形成策略和 OAuth 分开。
只在显式的原生 `reader_with_owner_grant` 入口中采用；现有 reader 不自动放宽或回落。
来源和输出 carrier 沿用 initialized profile，不另造 MCP 协议；scope hash 绑定完整授权及修订。

1. 授权绑定这个 Vault、确定的 Agent 身份、主体/项目、明确来源列表、敏感度上限、
   source_read、起止时间，以及主人明确批准的历史形成 `PolicyRef` 列表。
   不用通配来源或“永不过期”默认值，不自动纳入未来来源/策略修订。
   历史引用从原生不可变提交链核验，不能仅凭输入 JSON 或哈希声明获得权限。
2. **Morii 已明确同意此语义变化：**在这个新入口中，原形成策略的到期、后续修订或停用
   只结束/改变形成权限，不自动撤回已经单独批准的读取。获准读取的历史修订仍作为
   来源、主体、项目、敏感度及 access/egress 约束的证据，不能变成任意历史恢复入口。
   主人必须通过撤回这份读取授权来停读；记忆撤回/遗忘、来源删除及其依赖屏障始终优先。
   这允许“形成已停止，批准的既有记忆仍能读”，不是延长七天形成策略。
3. 不改旧记忆、原请求/回执或创世描述符，不让 Agent 获得 System/Owner 端口。
   授权不含创建、修订、采集、报告、Provider 调用或附件字节下载。
   source_read 沿用当前来源投影/文本权限；无原文权限时仍可能看到获准记忆自身的内容。
   保留敏感度下限、实体/别名证据及派生/回退依赖闭包；不得借授权引入未选来源。
4. 主人管理复用当前 OS Owner 身份、原生事务/未知结果恢复和恢复根隔离门槛。
   最小操作为查看、预览设置、确认设置、续期、撤回；输出完整授权元数据供审阅，
   不输出原文或令牌。续期只改授权期限；扩大范围另做完整预览与明确确认。
   续期/撤回产生新授权修订，立即使旧许可、缓存和旧会话失效；重开不能复活它们。
5. 保持许可最多五分钟、服务约四分钟换代。新许可期限取五分钟和读取授权剩余时间中较短者，
   授权到期立即拒绝；不靠延长 bearer 保持可读。服务在每次读取和换代时核验授权，
   不把进程启动时加载的配置视为撤回后的授权；选中授权的变更需要重新初始化会话。
   首片的 CLI 管理要求停止服务再打开唯一写入租约；OAuth 管理可复用状态文件锁并行运行。
   不增加热管理端口，手改磁盘或配置不能绕过租约/当前性检查。
6. OAuth 继续使用现有 authority/state lock；补最小客户端状态查看与主动撤回入口，
   不重写 OAuth。撤回客户端拒绝其现有 access/refresh 和待兑换 code；撤回 Vault
   读取授权后，即使 OAuth 尚有效，也不得返回记忆。两种撤回在主人界面中明确区分。
   当前服务只有一个配置的 Agent、bearer subject 为 owner；首片不扩展成多用户/多范围路由。

### 影响与代价

增加一个可重放的 Owner 授权变更记录、精确历史策略索引、显式原生读取入口和
对应服务绑定，复用既有投影与 OAuth。只给原 reader 新加一个布尔开关不能安全表达这个边界。
新的持久记录要求备份验证/重放认识该类型；旧二进制可能拒绝新记录，必须在采用说明中
明确版本要求并保留采用前备份，不能承诺任意降级。实现触及 Runtime 集成面时，同提交
更新 manifest 和采用说明；不修改 Runtime 仓库。

现有入口继续要求当前形成策略，保持此前语义。只有原生主人建立授权并在远程配置中
显式选择 `read_grant_id` 后采用独立读取；本片不会自动选择某份真实授权。

### 2026-11-12 接续：迁移前只读自检

已有 `read-status` 列出持久授权，但服务配置是否能取得读取许可原先只在 `serve` 时验证。
增加原生 `read-check <config>`，与服务复用配置检查和创建短许可的代码，再验证 opening
profile。它只返回当下 snapshot、授权模式、配置范围和临时 scope hash，不监听网络、
创建 OAuth 状态、执行召回或提交授权。结果不是可重用许可，后续启动仍重新核验。
已有唯一租约、恢复隔离、形成策略/独立授权分流保持生效；不改变授权模型或启动新阶段。
实际目录可写性、端口可用性、TLS 和真实客户端仍由对应后续验收负责。
