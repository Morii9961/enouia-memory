## 执行路线与出口

### A. 先完成可审阅的 PR 收束准备

1. 先读 AGENTS、本路线、两份状态文件及本机私人交接。检查当前 Git 与开放 PR；复用本次盘点，不重复全仓搜索或全套测试。
2. 保留本次未提交的状态/路线文档。后续保存文档时保持独立变更，不把它们混进已提交的 #113 功能补丁，也不覆盖第二工作树。
3. 核对 #110 → #112 的依赖；#113 可独立审阅。两个实现分支共同修改 ADR 登记及 Runtime 交接文本，整合时不能丢失任一说明。
4. 允许在独立临时集成分支准备组合源码及聚焦合成验证；它只是评审材料，不能等同于已合并或用于真实建库。最小检查覆盖 initializer 纯文本形成/重开、fresh 备份及恢复接续，并按实际 integration-surface 改动检查。未变证据不重复跑，不默认 full workspace。
5. 形成一份具体合并清单：最终 tip、实际跑过的检查、风险、#110 后将 #112 retarget 到 main 的顺序。此前“等待主人合并”仍有效；本次“继续工作”没有明确取消该约定。先完成可审阅准备，再在真正需要合并时提出具体请求，不在开工前重复问已确认范围。

出口：三 PR 的最终状态和组合证据清楚。所有新能力经主人合并后进入 B；若待合并，可先完成 M07 的文档修订和后续执行材料，不用未合并代码读真实材料。

### B. 完整纯文本预检

1. 从最终合并提交及独占构建目录准备正式 CLI。旧共享 target 已删除，不复用残留旧入口。
2. 私人 mapper 要换成最终纯文本模式：`attachment_retention: metadata_only`，完整绑定附件槽位且 `original:null`。旧附件归档 mapper/诊断不能直接沿用。
3. 保留完整文字来源、直接/上下文精确范围、说话人、分支、双时间、主体、敏感度及原分析字节和未知元数据。不伪造重新分析、Owner 确认或图片可重取证明。
4. 只读预检覆盖全轮所有计划及 journal 生命周期增长；整体 journal 16 MiB 约束不因分批而消失。静态单条通过、映射成功和旧附件探针都不能替代该检查。
5. 若超限，先给出具体失败点、规模和最小修复方案；不截断、丢源、删完成日志或任意提高预算。新增能力仍先合成验证和 PR，再用于真实材料。

出口：保存可核验的全量预检结果；明确原生写入尚未发生。容量通过后才进入 C。

### C. 真实本机交库与独立恢复

1. 在既有真实建库授权和持久用户数据目录内，通过原生 bootstrap 新建独立 Owner 根；不升级旧库，不将分析 bundle 改名成库。
2. 固定整轮输入、计划与运行绑定。中断保留原 packet/key/binding；未知只查原回执或显式恢复，不换键重发，不偷偷扩大读取策略。
3. 对账既有分析的全部选入范围、形成数、来源依赖及精确引文；关闭重开后验证分页/检索/来源可用与重复运行不增殖。
4. 关闭写入后导出，验证独立副本，并在隔离位置做恢复核验；激活前遵守停旧 Host 与恢复隔离条件。同盘合成往返不能写成真实独立备份证明。若独立介质/目标未定，完成其余交付准备并只询问这一缺失条件。
5. 保留原件、manifest、分析和所有恢复材料。删除旧资料必须在新库与独立恢复验收后列出准确路径并再次获得确认。

出口：私人验收记录包含准确合并版本、真实形成/重开/来源/恢复结果和未完成项。公开报告只写工程元数据，不写正文、私人路径或凭据。达到该出口后才向 Runtime 发 ready。

### D. Runtime 并行与后续

Runtime 负责版本采用、产品 UI、Owner 根入口、新候选与人工验收；Memory 不修改其 checkout，不接 Activity。ADR146 兼容采用准备可与 B/C 并行，产品真实接入依赖 C 的交库证据。不要让两个会话都重写已完成的 fresh 驱动。

跨聊天协调只发送实际 pin/aggregate、出口证据和剩余门槛，不发送私人内容或路径。用户已授权本次联系 Runtime 核对路线；如果新聊天不能确认继续消息的授权，先完成工程材料，不把别人要求回复当用户授权。

### E. 云端及后续单列

本机/Runtime 闭环之后再按明确授权处理实际来源范围、敏感度、source text、期限、VPS/TLS、备份和停旧主的切换条件。OwnerReadGrant 的实现完成不等于真实授权已经选定。只读 ChatGPT 互通、持续采集/写入、MV-9 完整迁移故障出口和 MV-10 离线同步分别排期，不自动开始。

## 验证、排期与结束条件

本次文档只复用已保存证据，没有运行产品测试、构建、Memory schema 或 surface checker。Dashboard 的快照格式检查只判断能否导入，不代表代码/实际数据验收。

下一会话按改动风险选择聚焦检查；新库容量和实际恢复有必要时执行对应真实流程，不能为“看起来在推进”反复跑不相关矩阵。首次失败和复跑结果都保留。

本机新库加 Runtime 首轮验收暂按 1–2 个工作周粗排，前提是 PR 收束、容量通过且入口无结构性缺口；云端只读另预留 1–3 个工作周，置信度低。它们不是承诺日期。下一次估时在 A/B 出口及 Runtime 首个入口范围确定后更新；完整自动采集/同步路线暂无可靠完工日。

不得擅自部署、授予真实长期读取、删除原件或扩大阶段。已确认的纯文本、既有分析和本机建库目标不再重问。若遇到合并或外部条件门槛，报告完成的具体材料和唯一所缺条件，继续能独立推进的授权工作。
