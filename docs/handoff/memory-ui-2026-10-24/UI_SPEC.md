> 历史材料（2026-10-24，2026-11-02 补入版本管理）。实现状态、暂停与授权只描述原日期；当前事实以主线实现、分阶段计划及最新验证报告为准。本文不启动任何工作。

状态：2026-10-24 的交接提案；用于正在进行的 Runtime UI 重构。本文不是新 Schema、设计 token 冻结或新 MV 阶段启动令。契约可用性见 [CONTRACT_READINESS.md](CONTRACT_READINESS.md)。

**目标修正：** Morii 要完全自动化，参见 [06](../../design/memory-evolution-2026-10-24/06-automation-and-ombre-migration.md)。日常不要求逐条接受候选；“系统记住了什么、为何形成、为何此时想起、怎样自动重评与淡出”是主任务。旧三栏审阅方案只保留为可选纠正/诊断能力。新自动采用状态需要后端契约，不能把当前人工确认记录换个标签当成已经自动化。

**执行边界：** Claude 新 Session 接续 Runtime `redesign/explore` / `98cd21261e510013c845b722f40ec50d861e0f72` 的五方向探索，不新起一套产品壳，也不替 Morii 选定视觉方向。当前 `DESIGN.md` 仍待定。此页的工作区、三栏、颜色和390px讨论都是 Memory 区域的产品输入，不覆盖 Runtime `AGENTS.md`、`docs/design-kit/` 和已经形成的方向材料。正式后端仅 Core-1 契约与纯规则；MCP 新接线暂停，已有代码保留。完整集成边界见 [RUNTIME_BOUNDARY_AND_INTEGRATION.md](RUNTIME_BOUNDARY_AND_INTEGRATION.md)。

## 1. 从 Morii 的问题组织界面

Memory 的主任务应从“管理多少条记录”转为“我经历了什么、Enouia怎样理解、现在为什么想起它”。进入页面时，默认展示可理解的记忆、系统自动形成与重评的进展，以及 Morii 可自愿查看的变化；不要求 Morii 清空候选队列。数据库、锁、队列和工具协议进入可展开诊断。

建议保留 Runtime 七个主产品面的边界，Memory 内部提供五个工作区；Context 与 Sessions 通过对象链接互通，不把 Activity/Usage 搬进 Memory。

| 工作区 | Morii 的问题 | 主体内容 |
|---|---|---|
| 记忆 | 现在留下了什么？ | 记忆格/列表、记录状态与业务当前性分开、筛选、统一详情 |
| 时间 | 那段时间发生了什么？ | 日/月时间线、主题泳道、覆盖日历、未知时间区 |
| 关联 | 哪些经历相互关联？ | 星图、主题簇、替代链、证据链的可解释视图 |
| 形成 | Enouia 怎样理解与更新？ | 自动形成/重评轨迹、暂存假说、冲突解释、可选纠正与历史diff |
| 召回 | 这一刻为什么想起这些？ | 现有召回解释、明确标识的合成实验室 |

“Vault 与恢复”留在设置/管理，不与日常时间线抢第一层入口；锁定、连接、Provider 失败只在影响当前任务时显示。新工作区未接真实后端时，用清楚的“设计预览 / 合成样例”呈现，不能在原生真实记忆界面静默回退到 demo。

### 布局比较与选择

**方案 A：导航—内容—证据的三段式。** 适合桌面长文本、候选对照和证据追踪，能复用 Runtime 现有 MemorySurface 的骨架，作为 Memory 局部候选方案。它不替代五方向探索，也不是已选全局实施基线。

```text
┌ Runtime 导航 ┬ Memory：记忆 / 时间 / 关联 / 形成 / 召回 ────────────────┐
│              │ 搜索     记录范围        视图切换     业务当前性        │
│              ├─────────────────────────┬────────────────────────────┤
│              │ 主内容：格 / 轴 / 图    │ Inspector                  │
│              │ 当前筛选与覆盖说明      │ 陈述、状态、何时成立        │
│              │ 可保留滚动位置          │ 来源、替代、修订、相关经历  │
│              │                         │ 明确的审阅/纠正入口        │
└──────────────┴─────────────────────────┴────────────────────────────┘
```

**方案 B：全屏沉浸星图，选中才显示面板。** 适合探索，对审核、可访问性和窄屏较弱，保留为“关联”工作区的一种视图，不作为全产品默认入口。

建议评估 A 的理由是：Morii 看见一个记忆点后，可以在同屏检查来处与形成过程。持续存在的证据面板能保持上下文；是否采用固定三栏仍由 Claude 结合现有方向与最小窗口评估。

## 2. 视觉方向：安静的记忆工作台

复用 Claude 正在重构的设计权威与方向材料。实际 `redesign/explore` 仍以 Quiet Runtime 作基线，五个方向尚未收敛；本包不指定它必须保持深色，也不让 Memory 自立另一套品牌主题。九图提供任务与交互参考，最终外观随当前探索与 Morii 选定结果。

可沿用的颜色角色如下，数值来自已读取的 Quiet Runtime 文件，仅供映射，最终值以实际重构 token 为准：

| 角色 | 旧副本值 | 使用方式 |
|---|---|---|
| Canvas | `#0C1117` | 主工作区背景 |
| Surface | `#111820` | Inspector、弹层、局部容器 |
| Primary | `#E7EDF2` | 正文和操作文本 |
| Secondary | `#9BA9B6` | 次要说明；须实际测对比度 |
| Ice | `#9FC2D2` | 选择、聚焦、证据路径 |
| Pending | `#D8BC8A` | 待审/需复核，始终伴文字或形状 |

颜色承担状态，不承担主题真伪、重要性或关系强弱的判断。多个故事主题使用可区分的线型/标签，色彩只辅助识别；冲突、敏感、删除与待审不能复用同一种紫色。

字体角色复用 `Segoe UI Variable` 与现有中文系统回退，正文建议 15–16px、行高 1.55–1.7；日期/ID/版本使用现有 `Cascadia Mono` 回退。时间线月份可用较大的细字重形成节奏，避免为参考图的衬线标题引入在线字体或大段斜体中文。

**唯一的识别性元素：证据脉络。** 选中记忆时，当前视图中与它有关的时间点、候选、来源和替代关系以同一条细线/同一选中状态串联。线只连接已有、可解释的对象关系；未知区间断开，推断关系用虚线并写明“待确认”。不做不停呼吸的装饰星空。

设计自检：去掉大数字概览、随机渐变、满屏漂浮卡片。首屏让 Morii 找到一段记忆，并能在同屏看见“它为什么存在”。日历与图表服务于回到证据，不能成为另一套成就统计。

## 3. 统一详情：所有视图共用同一对象

卡片、时间点、星图节点和候选关联点击后都进入同一 Inspector。视图切换保留选中对象、筛选、时间范围与滚动位置；返回后不丢失原来的阅读位置。

详情依次显示：

1. 陈述与明确状态：待审候选 / 已确认 / 存在冲突 / 已被替代 / 已归档 / 需复核。已确认只表示可信审核完成，不等于外部独立证实。
2. 内容与适用情境：五种现有类型、主体、项目、范围、有效时间。事实发生、系统收到、系统确认、当前修订各自标名；缺失显示“未记录”。
3. 为什么留下：候选的 reason、原始证据类别、Morii 确认记录；模型产生的解释标“模型提议”。
4. 证据：精确来源修订、支持哪一陈述、来源角色、片段、附件可用性。先显示片段，需要时再分页读取，始终按纯文本呈现。
5. 变化：旧陈述、新陈述、替代范围、冲突未解决项；“更新于”不替代事件时间。
6. 控制：请求纠正、审核、归档/遗忘入口沿用真实 plan/diff/confirm 语义。只读原型中为禁用控件并解释依赖，不制造“已保存”toast。

不同对象使用不同头部：来源不是记忆；候选不是 Canonical；checkpoint 的 provisional 状态不能只藏在详情底部。context_source_refs 是“模型曾读取的上下文依赖”，与“支持该陈述的证据”分组，不能把两者总数相加成“多源印证”。

存储 status 与业务当前性分别显示：active 记录仍可能过期、尚未生效或冲突；superseded 记录也可能在新决定未来生效前仍对当前业务有效。列表的 includeInactive 只是扩大管理范围，不是“当前/历史真值”切换。只有后端明确返回的 currency 才显示为对应当前性，不从 summary 的几个 flags 猜出 current_supported。

`memory_read` 只接受 memoryId，读取当前pin的最新修订。Inspector 应校验所选列表 revision 与返回 revision；不匹配时更新选择并说明记录变化，或要求重新读取列表，不能把旧摘要/旧关系与新正文拼在一起。现有接口不能按选择的旧revision读取历史正文，历史修订阅读需后续契约。

## 4. 记忆格与列表 · ref-01

记忆格适合漫游、列表适合精确找回。每条只放标题、简短陈述、类型/当前性、时间语义、证据入口；不同时塞满全部标签。列表与卡片保持相同排序、选择、分页与可用操作。

当前接口可先做“按最近修订浏览”，清楚写“最近更新”。仅对已加载页进行的类型/状态筛选必须标“当前已加载范围”，不能让 Morii 误以为已筛全库；没有后端全量 facets 时不显示精确全库分类计数。搜索现有字面检索不能标成语义理解或向量召回。

收藏/钉住、情绪、被打动、长期强度等新字段先用设计样例表现；没有存储契约时不接真实写入，不借标签伪装正式属性。

## 5. 时间工作区 · ref-02 / ref-06 / ref-08 / ref-09

### 四种时间不能混为一个日期

| 时间 | 回答的问题 | 表现 |
|---|---|---|
| 发生时间 | 事情何时发生？ | 日/月时间线主轴；未知进入独立分组 |
| 有效时间 | 这条偏好/决定何时适用？ | 区间带，与发生点分开 |
| 收到时间 | 系统何时拿到材料？ | 覆盖层，不回填为发生时间 |
| 系统知道/确认时间 | 当时已经知道、确认了吗？ | 后续双时态查询入口；不由前端自行重建 |

业务区间与日期精度的依据来自具体记录/来源。只有月份的记录显示月范围，不自动填 1 日；时区缺失/原时间无法解析时保留未知，不用浏览器当前时区猜测。显示时区可切换，但同一筛选的日界线和计数必须一致，夏令时与跨午夜记录不重复计数。

### 日/月时间线

默认显示月，展开日，再展开当天记忆；月份侧边导航可定位。当前后端只能拿到最近修订行时，先交付明确标为“记录更新时间”的版本，不能把它冒充完整人生时间线。事件/来源时间全量时间线等待后端授权分页投影。

### 主题泳道与并行事件轨

以可调整的主题泳道排列“持续事件/项目/经历”，上层叠加资料覆盖；横向缩放天/周/月，纵向展开主题。一个事件可关联多个主题而非强制唯一分类。线段端点表示有证据的开始/结束，未知端用开放端帽，只有若干离散证据时用点连虚线，避免画成持续发生的实线。

主题名来自明确分类或标识为模型建议；不从图片里的私人叙事抄一套人物/亲密关系分类。类别只在当前授权对象里聚合，隐藏记录不通过密度、空轨或总数泄漏。来源重复导入、模型对同一段材料的重复总结，不增加“独立证据”密度。

### 覆盖日历

三层开关为“收到的材料 / 待审候选 / 已确认记忆”，层名与计数口径始终可见。没有全库来源统计时显示“已加载范围”，未来全量覆盖需后端聚合。某天为零只代表所选范围无记录，不写“这天没有发生什么”。不以 Activity 活跃天数补齐记忆覆盖。

## 6. 关联与星图

优先让图回答“这条记忆依赖什么、曾如何变化”，再做语义聚类。初版选中节点的可解释邻域优于全库毛线团。

| 关系 | 可否当事实边 | 视觉 |
|---|---|---|
| 记录中的证据引用 | 可显示引用关系；不自动等于独立印证 | 实线，标签“来源” |
| 明确 supersedes | 可显示替代关系 | 有向线，显示生效时间未知状态 |
| 同主体/项目/标签 | 可显示共同属性；不表示双方有现实关系 | 分组/轻连线，按需开启 |
| context_source_refs | 可显示生成依赖；不作为支持证据 | 单独线型与图例 |
| 向量接近/模型联想 | 需新后端契约，仅是建议 | 虚线，“语义关联建议” |

节点大小先统一。未来如编码强度，必须能解释来源与更新时间，不能让“大”暗示“更真实”。平移、缩放、定位、返回选中节点都提供按钮；每个图有并列可读的关系列表。图布局可本地计算，但关系授权、全库分页、聚类版本与完整性由后端决定。

为避免 N+1，当前 pin 可先只展示**已读取的有界集合**，例如用户显式选择不超过 25 条记忆后再读详情；不自动全库抓取。产品级星图需要专门的授权聚合投影，不能靠后台遍历全部正文实现。

## 7. 自动形成与导入，保留可选纠正 · ref-03 / ref-07

目标模式显示来源接收、提炼、系统采用/暂存、重评与巩固的观察轨迹，不以人工批准作日常闸门。这些是产品叙述，不是本页冻结的新状态枚举。没有真实后端能力时只出现在独立合成预览；不把旧提案队列自动点击通过，也不把原有 owner review 改名为“系统采用”。

现有 pin 仍保留原来的人工审阅事实。其可选管理面可比较左队列、中候选、右证据/冲突三栏：选文件 → 解析/导入任务 → 抽取或提案 → 待审 → 查看 diff → 确认。每一步显示实际保存边界，解析成功不自动勾选“已理解”。该兼容流程不是全自动核心的最终入口。

每条审阅先回答三个问题：这句话由什么支持？相对于当前记忆改了什么？是否超出了来源能证明的范围？来源缺失、上下文缺失、证据冲突、模型推断各有文字状态。重复和矛盾候选给比较入口，不以相似度百分比自动合并。

编辑保留本地当前窗口草稿，并明确未提交；不得为方便持久化而把真实正文写 localStorage。切换对象时提示处理未提交内容；发生 revision conflict 后保留草稿、重新读取并重新生成 plan，旧确认权限作废。批量审核只作用于明确选择的精确版本，不能用“全选”隐含通过未加载对象。

当前 Workspace 的审核编辑只可传 editedContent。Canonical/govern 内存在分类、标签、时间或专用details字段，不代表页面可编辑它们；现有 EditAccept 不接收 details。正文以外的编辑先禁用并说明依赖，等待获批 IPC 扩展或使用已存在且匹配的后台候选生成路径，不能从页面硬传未知参数。

历史批处理只在实际 pin 有相应命令时出现，显示完整任务/批次范围和已保存状态。准备请求、审查确切 body、确认发送、查看结果分开；恢复保存任务不重新生成任务，不自动调用真实 Provider。

## 8. 召回解释与实验室 · ref-04 / ref-05

可以借鉴“五阶段”的可读顺序，但 Enouia 的资格门槛必须先于评分，且不能被 sliders 绕过：

```text
输入与范围 → 当前权限/删除/来源/时效资格 → 已有检索与排序
          → 预算与完整性 → 最终 Capsule / 未进入原因
```

目前 `ContextInspection` 有纳入/排除、reason、rank、token_cost、source_reachable、truncated，适合展示“为什么进入/没进入”；没有 topic/emotion/time/importance 的可调权重与逐项分数。UI 应展示真实原因与排名，不伪造漂亮的堆叠分数。

实验室分三种清楚的模式：

- **合成演示**：完全内存 fixture，屏幕固定标“合成样例”；可自由改参数、对照案例，不调用 IPC，不写 Vault，不发外部请求。
- **已保存召回的解释**：按可用 capsuleId 读取既有 inspection；当权限/删除屏障变化而无法再读取时，停止展示旧正文。
- **保存新的召回预览**：未来经明确授权使用现有 `context_preview`，按钮写“保存召回预览”；它会写入 Capsule/Inspection，不能称为只读模拟。拖动参数不运行；现有接口不支持的参数保持禁用并说明依赖。

主动唤醒与自然遗忘的预期体验先设计为“建议卡片与历史解释”：为什么此刻值得回看、为何暂不再主动提起、稍后提醒/关闭本类建议。真正触发、冷却、时间推进、强度更新、归档/清除由后端定义；前端不能定时修改记忆或靠打开卡片增加强度。尚未实现时显示“设计提案”，不制造“系统正在陪你回忆”的运行状态。

## 9. 状态与失败

| 状态 | 需要看见的说明 | 可执行动作 |
|---|---|---|
| 尚未连接 / 锁定 | 当前没有可读记忆 | 显式选择/解锁；不自动开库 |
| 初次载入 | 当前任务与范围 | 保留页面结构，避免闪成“0条” |
| 无结果 | 当前检索或范围没有匹配 | 清除筛选/改查询 |
| 部分范围 | 已加载多少，是否还有分页 | 继续加载；不得显示全库统计 |
| 索引暂不可用 | 搜索暂不可用，原列表是否仍可读 | 按现有可重试语义恢复 |
| 来源缺失 / 时间未知 | 哪个证据/时间字段缺失 | 查看可用信息或提出修复 |
| 状态读取失败 | 当前 Vault 状态未知 | 清除敏感内容与提交能力，重新读取 |
| 结果未知 | 操作可能已提交，尚未确认 | 保留原始包/键，显式查询恢复；不自动重发 |
| plan过期 / revision冲突 | 当前内容已变化 | 保留草稿，重新读取/规划/确认 |
| 权限改变 / 删除 / 换库 | 旧内容已不再可用 | 立即清除面板、图索引、选择和派生文本 |

“重试”只在返回 retryable 时存在。重试同一写入保持原 payload 与 key；编辑内容建立新请求。旧 A 查询不能覆盖新 B 结果，A→B→A、unmount、状态失败、Provider 改变和 Host 断连后的迟到响应都需失效保护。沿用 Runtime 已有 hooks、observation identity 与生命周期门禁；重构不能只保留视觉。

授权也按对象域区分：MemoryRead 不隐含 SourceRead 或 ContextRead，来源/解释入口须等待各自授权结果。未来图与时间聚合要定义单独的授权投影；不能借已有 Memory读取权限或六个MCP工具扩出全库关系/统计能力。归档记录可经管理列表含非活跃范围和详情查看，但现有 search 即使 includeHistorical 仍过滤 archived，不能提供名为“搜回全部归档”的假入口。

## 10. 键盘、响应式与性能

使用语义化 button/link/list/form；视图 tab 若采用 ARIA tabs，完整实现方向键、Home/End 与焦点模型，否则使用普通导航。不要给普通卡片网格套半套 aria-grid。提供跳到内容入口、可见 focus、搜索可达；快捷键可发现且不覆盖输入框与系统组合键。

Inspector 普通阅读采用区域面板，不锁焦点；模态确认才使用 dialog、焦点回收和 Esc。Escape 关闭顶部轻面板，不能确认写入或遗忘。图表可用键盘在邻居列表选择，缩放有 `+ / − / 重置` 按钮，拖拽均有点击替代；焦点项被虚拟化时仍可正确定位。计数加载完成用温和 live region，一次性报告，不逐点播报动画。

文字对比度按实际 token 测量；正文目标 4.5:1，状态和图边不只靠颜色。目标可点击区域至少 44×44px，密集桌面行可有较小视觉按钮但扩展命中区。200% 缩放不裁掉确认按钮；文字可选、换行、放大。

| 宽度/条件 | 布局 |
|---|---|
| ≥1280 CSS px 且三栏内容足够 | 导航 + 主视图 + Inspector；审阅可三栏 |
| 900–1279 | 侧导航可收拢，Inspector 变抽屉/分屏 |
| <900 或 200% 缩放导致拥挤 | 单一任务页，详情走可返回页面；保留原筛选与位置 |
| 约390手机预览 | 浏览→当日→详情→来源/审阅分步；底部至多5入口 |

这是 Memory 区域的布局研究。实际 Runtime 当前最小原生窗口为1100×700，探索截图口径为1100/1440/1920，快速搜索为560×420；390px仅是本包概念预览，不授权修改原生最小窗口、全局导航、产品语言、独立手机端或远程访问。缩放可访问性仍应在当前窗口约束中处理。

读取采用后端 cursor 与提交绑定；游标失效后重新读取并提示范围更新。首屏只加载当前窗口和一页，列表窗口化保留焦点；星图布局只在集合改变时运行，稳定位置可复用，隐藏页面暂停动画/轮询。未知数据先降级列表，不为数千节点引入重型图引擎。选择图技术前用合成规模样例测量，按瓶颈决定 SVG、Canvas 或 worker，现阶段不新增依赖。

动效只用在展开、选中与空间连续性：常规反馈约120–180ms，布局过渡约180–240ms，最终按现有系统调校；加载、星图、召回均无无限装饰循环。`prefers-reduced-motion` 下用静态切换。屏幕捕获、DOM dump、console、错误遥测和测试快照只允许合成内容。

## 11. 前端交付顺序与验收

本表是建议工作包，不是授权 Claude 自动完成新领域阶段或 pin 迁移。

| 包 | 可以先做什么 | 退出条件 |
|---|---|---|
| UI-A | 接续现有方向与比较稿，映射 Memory 局部信息架构和共享Inspector | 保留探索成果；不替 owner 选设计、不改全局shell |
| UI-B | 独立合成的自动形成/重评/巩固观察，记忆格/轴/图/实验室互通 | 无真实IPC或假生产状态；用户不承担清队列任务 |
| UI-C | 旧pin兼容面：记忆列表/详情、现有召回解释、可选人工纠正 | 当前性/版本/权限准确；现有确认与恢复语义保留 |
| UI-D | 单独受控采用已交付的时间/关系/覆盖契约 | pin与adapter同一集成负责人串行修改，完整性可解释 |
| UI-E | 后端自动生命周期出口通过后接真实形成/唤醒/淡出观察 | 真正自动准入，不伪造owner批准；撤回、冷却与恢复有效 |

设计原型至少包含：空库、仅候选、已确认但冲突、来源缺失、时间未知、部分覆盖、被替代、锁定、结果未知、只读模式。实现检查以变更风险和实际 Runtime 要求为准；文档交接不运行构建。真正 UI 实施时验证窄屏/缩放、键盘、屏幕阅读、迟到响应和当前 pin；合成渲染通过与 Morii 的日用体验验收分别记录。

MCP暂停不删除已有实现，也不移除旧Workspace入口。Host切换、Agent登记与云端不是本次UI重构的依赖；Core后端只提供契约与Memory区域挂载所需语义，路由、设计token、共享shell与native lifecycle由Claude现有Runtime权威负责。
